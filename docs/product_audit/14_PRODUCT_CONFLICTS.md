# 14. Расхождения кода, интерфейса и документации

Найдено во время аудита. Каждое расхождение описано так, чтобы его можно было
либо починить, либо сознательно оставить — но не пропустить молча.

Помечено:
* 🔴 **видно пользователю** — влияет на то, что продавец думает о продукте;
* 🟡 **внутреннее** — влияет на разработку и поддержку;
* ⚪ **историческое** — оставлено намеренно, но требует осторожности в текстах.

## 🔴 К-1. Команда `/prices` обещает расписание, которого на экране нет

**Что говорит интерфейс.** В списке команд Telegram (кнопка «☰ Меню») стоит
строка:

```python
("prices", "Цены и расписание")
```

**Что делает код.** `/prices` открывает прайс-лист — цены всех товаров
постранично, по 10 на страницу. На экране четыре кнопки: «◀️ Назад»,
«Ещё ▶️», «🔄 Обновить», «⬅️ Меню». **Никакого расписания там нет.**

Расписание поднятий живёт в другом месте — `sched:*` в
`handlers/selenium_settings.py`, доступ через ⚙️ Настройки и ⚡ Автопилот.

**Почему это важно.** Продавец, ищущий расписание, идёт по этой команде и не
находит его. Хуже: менять цены бот **не умеет вообще**, а строка «Цены и…»
в меню читается как обещание, что умеет.

**Proof:** `bot/commandlist.py:37`; `bot/handlers/prices.py:180`
(`cmd_prices`), `:110`–`:114` (все кнопки экрана); докстринг модуля прямо
говорит «Только просмотр».

**Варианты решения:** переименовать пункт в «Прайс-лист» либо «Цены
(просмотр)». Правка в одну строку, в `commandlist.py`.

## 🔴 К-2. Фоновая выдача звёзд не закрыта тем же флагом, что интерфейс

**Что заявлено.** `CLAUDE.md`, раздел про скрытый плагин: плагин прячется
целиком, и «уходят разом: кнопка на экране плагинов, строка про звёзды в его
тексте, `/stars` и вся диагностика Fragment из `commandlist`, строка в
приветствии, прокси на экране „Мои прокси" — и обе точки входа фоновой выдачи
в `tasks/manager.py`».

**Что в коде.** Две точки входа действительно закрыты — гейт стоит **внутри**
функций:

```
manager.py:3434  в _maybe_ask_stars_username    → if not stars_shown(user_id): return
manager.py:3472  в _maybe_deliver_stars_reply   → if not stars_shown(user_id): return
```

Но в `_tick_auto_locked` есть **ещё три** фоновых входа, и они проверяют
только `plugins.auto_stars.enabled`, без `stars_shown`:

```
_stars_pending_sweep    (manager.py:3751)  → if not p.get("enabled"): return ""
_stars_balance_watch    (manager.py:3867)  → if not p.get("enabled")…
_stars_session_watch    (manager.py:3814)
```

**Практическое следствие.** Продавец, включивший AutoStars **до** того, как
флаг был поставлен, продолжит получать предупреждения о балансе кошелька и
обработку очереди «ждём @ник» — при том, что экрана, на котором это можно
выключить, у него больше нет. Ровно та беда, которую флаг и задумывался
предотвратить: «убрать экран, но оставить фоновую работу — хуже всего».

**Насколько вероятно.** Невелика: чтобы попасть в это состояние, надо было
включить плагин до появления флага. Но проверить это по данным нельзя, а цена
— чужие TON.

**Proof:** `bot/features.py` (`STARS_HIDDEN`, `stars_shown`);
`bot/tasks/manager.py:3751`, `:3814`, `:3867` против `:3434`, `:3472`.

**Вариант решения:** добавить `stars_shown(user_id)` в три сweep-функции — или
проверить его один раз в `_tick_auto_locked` перед всей веткой AutoStars.

## 🟡 К-3. «Английских комментариев не осталось» — осталось 36 мест

**Что заявлено.** `CLAUDE.md`: «Английских комментариев в исходниках не
осталось (28.08, переведено 1150 мест). Если появились снова — это правка,
написанная не по правилу».

**Что в коде.** 36 докстрингов в 14 файлах написаны по-английски или
преимущественно по-английски. Среди них — **докстринги целых модулей**, то
есть первое, что читает новый разработчик:

| Файл | Мест | Примечание |
|---|---|---|
| `automation/panel.py` | 11 | самый большой модуль проекта |
| `handlers/panel_items.py` | 4 | |
| `tasks/manager.py` | 4 | |
| `automation/market.py` | 3 | |
| `handlers/autopilot.py` | 3 | **включая докстринг модуля** |
| `automation/position.py` | 2 | **включая докстринг модуля** |
| `automation/stars.py` | 2 | |
| `stats_source.py` | 1 | **докстринг модуля, целиком по-английски** |
| ещё 6 файлов | по 1 | |

**Почему это стоит починить.** Не из педантизма: правило языка нужно, чтобы
следующая правка писалась по нему. Документ, объявляющий работу законченной,
когда она не закончена, перестаёт быть ориентиром — и следующий английский
докстринг никто не заметит.

**На продукт не влияет.** Продавец этих строк не видит.

**Как проверить:** скрипт, которым это найдено, разбирает AST и считает
английские служебные слова против кириллицы; он воспроизводим и может стать
тестом.

## ⚪ К-4. `auto_withdraw` — имя обещает автоматику, которой нет

**Что в коде.** Ключ настроек называется `auto_withdraw`, но автовывода не
существует: деньги переводит человек, нажимая кнопки. Внутри лежат
**реквизиты**: `panel_balance_id`, `panel_action_key`, `panel_values`.

**Почему оставлено.** Переименование потеряло бы реквизиты у тех, кто их уже
заполнил. Решение осознанное, и в самом коде стоит комментарий: «Автовывода
нет: деньги переводит человек, а не расписание — ключ остался прежним, чтобы
уже настроенные реквизиты не пропали».

**Что требуется от документации и маркетинга.** Называть это **реквизитами
вывода**. Формулировка «автовывод» попадает в UNSAFE
(`07_MARKETING_CLAIMS.md`).

**Proof:** `bot/storage.py` (`_DEFAULT_SETTINGS["auto_withdraw"]`).

## ⚪ К-5. Наследие однопозиционной версии слежения

**Что в коде.** В `promo_position` рядом со списком наблюдений `watches[]`
лежат поля от прежней версии, где на магазин приходилась одна страница:
`url`, `max_position`, `min_price`, `last_check`, `last_pos`,
`last_alert_pos`.

**Статус.** Читаются **только при миграции** старых настроек в новый формат.
Живой логикой не используются.

**Риск.** Правка «максимальной позиции» в корне `promo_position` выглядит
работающей, а на самом деле ни на что не влияет — пороги живут в каждом
наблюдении.

**Proof:** `bot/storage.py` (`_DEFAULT_SETTINGS["promo_position"]`,
комментарий «Наследие однопозиционной версии»),
`bot/automation/position.py:91` (`watches`).

## ⚪ К-6. Два механизма ответов сосуществуют

**Что в коде.** Работают оба:
* `auto_reply` / `auto_events` / `auto_rules` — прежний механизм, отвечает на
  **событие заказа** (новый заказ, возврат, подтверждение);
* `autoreplies` — нынешний, отвечает на **письмо покупателя**, с правилами,
  паузами, лимитами и тихими часами.

**Это не дубль:** они реагируют на разные вещи, и оба нужны.

**Проблема — объяснимость.** Два похожих названия, два места настройки, и
разницу между ними нельзя уместить в подпись кнопки. Для продавца точка входа
одна — ⚡ Автопилот, где они стоят разными строками в одной группе.

**Что делать документации.** Никогда не называть их одним словом
«автоответы». В текстах: «ответ на событие заказа» и «ответ на сообщение
покупателя».

**Proof:** `bot/storage.py:_DEFAULT_SETTINGS`, `bot/handlers/autopilot.py`
(`AUTOMATIONS` — ключи `answer` и `reply` стоят рядом).

## 🟡 К-7. Число тестов в документации и в прогоне расходится на единицу

**Что заявлено.** `CLAUDE.md` и `docs/TECH.md`: 3198 тестов.
**Что считает `grep`:** 3199 функций `def test_`.
**Что говорит прогон:** `Ran 3198 tests`.

Расхождение — одна функция `def test_*`, которая не собирается unittest
(вложенная, в неподходящем классе или намеренно не запускаемая). На продукт не
влияет; упомянуто, чтобы следующий человек не искал поломку там, где её нет.
