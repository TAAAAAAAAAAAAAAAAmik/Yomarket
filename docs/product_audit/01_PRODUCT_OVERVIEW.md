# 01. Обзор продукта

## Что такое Юмаркет Менеджер

Telegram-бот, который берёт на себя рутину продавца цифровых товаров на
маркетплейсе Юмаркет: следит за заказами, отвечает покупателям, выдаёт коды,
поднимает объявления, возвращает распроданное в продажу и показывает, сколько
магазин заработал.

Продавец подключает свой магазин один раз — вставляет токен Integration API — и
дальше работает из Telegram, не открывая сайт маркетплейса.

**Proof:** `bot/handlers/start.py` (подключение по токену), `bot/main.py:653`
(`main()` — сборка бота), `bot/tasks/manager.py:1086` (`TaskManager` — фоновая
работа).

## Для кого

Продавец цифровых товаров на Юмаркете: игровая валюта, аккаунты, ключи,
подарочные карты. Профиль подтверждается устройством продукта, а не
предположением:

* весь интерфейс рассчитан на один магазин в фокусе и несколько подключённых
  (`bot/handlers/accounts.py`);
* автовыдача устроена под товары, у которых остаток — это сами коды
  (`bot/automation/giftcards.py`, 13 видов карт);
* язык интерфейса — русский, деньги — рубли (`bot/orderfields.py:409` `money`).

## С какими платформами работает

| Платформа | Роль | Как обращаемся | Proof |
|---|---|---|---|
| **Юмаркет, Integration API** | заказы, чаты, товары, остатки, публикация, баланс | `https://api.yoo.market/integration/v1`, Bearer-токен продавца | `bot/api/yoomarket.py:111` |
| **Юмаркет, панель продавца (Nova)** | то, чего нет в API: поднятие, вывод, отзывы, создание товара, журнал операций | `https://panel.yoomarket.net`, сессионные куки | `bot/automation/panel.py:13` |
| **Юмаркет, публичная витрина** | позиция товара в выдаче, цены конкурентов | чтение страниц | `bot/automation/market.py`, `bot/automation/position.py` |
| **AppRoute** | поставщик кодов подарочных карт и Robux | `https://approute.io/api/v1`, заголовок `X-API-Key` | `bot/automation/approute.py` |
| **ns.gifts** | второй поставщик, для сравнения закупочной цены | API поставщика | `bot/automation/nsgifts.py` |
| **Fragment + TON** | покупка Telegram Stars | сессия Fragment, подпись BOC, TonCenter | `bot/automation/fragment.py` — **раздел скрыт**, см. ниже |

## Какие основные задачи решает

1. **Не пропустить заказ и письмо покупателя.** Опрос заказов раз в минуту,
   чатов — раз в 10 секунд для «горячих».
2. **Ответить покупателю без продавца.** Правила автоответа, паузы, лимиты,
   тихие часы.
3. **Выдать товар без продавца.** Подарочные карты и Robux — код уходит
   покупателю по факту оплаты.
4. **Вернуть товар на витрину.** Автовосстановление распроданного и снятого.
5. **Держать объявление наверху.** Поднятие по расписанию, по интервалу и по
   позиции в выдаче.
6. **Показать деньги.** Статистика из журнала операций панели, а не из того,
   что бот успел увидеть.

## Архитектура глазами пользователя

```
Продавец в Telegram
        │
        ├── нажимает кнопки → экраны бота (≈412 обработчиков нажатий)
        │
        └── ничего не делает → бот работает сам:
                ├── раз в 10 с  — читает «горячие» чаты, отвечает по правилам
                ├── раз в 1 мин — читает заказы, шлёт уведомления, выдаёт коды,
                │                 напоминает о зависших, заливает копии
                ├── раз в 30 мин— поднимает объявления, следит за позицией,
                │                 возвращает распроданное, проверяет баланс
                └── раз в 6 ч   — удаляет данные тех, у кого кончилась подписка
```

Существенное для маркетинга следствие: **бот живёт на сервере, а не на
компьютере продавца.** Компьютер держать включённым не нужно, телефон — тоже.
Продавец может выйти из Telegram, автоматика продолжит работать.

**Proof:** `bot/tasks/manager.py:1269` (`_user_loop`), `:1279` (`_chat_loop`),
`:4805` (`_auto_loop`), `:1170` (`_purge_loop`).

## Что в продукте наиболее ценно

Оценка по трём признакам: работает без участия человека, трогает деньги,
случается ежедневно.

| Функция | Почему ценна |
|---|---|
| **Автовыдача подарочных карт** | покупатель получает код без продавца, в любое время суток. Это прямая замена ручной работы у каждого заказа |
| **Автоответы с паузами и лимитами** | письмо покупателя не ждёт продавца; замедление опроса при этом видно, а не скрыто |
| **Автовосстановление распроданного** | товар, ушедший с витрины после продажи, возвращается сам. Без этого магазин молча перестаёт продавать |
| **Продвижение по позиции** | бот смотрит на реальное место товара в выдаче и поднимает, когда он опустился, а не по таймеру вслепую |
| **Статистика из журнала панели** | цифры не зависят от того, работал ли бот в момент продажи |
| **Несколько магазинов в одном боте** | переключение между аккаунтами без повторного подключения |

## Что требует осторожности в маркетинге

Перечислено кратко; полный разбор — `07_MARKETING_CLAIMS.md` и `08_LIMITATIONS.md`.

1. **Изменение цены бот не умеет** — намеренно, у товара в панели нет такого
   поля. Обещать «управление ценами» нельзя.
2. **Автовыдача Telegram Stars скрыта** (`features.STARS_HIDDEN = True`).
   Её нет у продавца ни кнопкой, ни командой.
3. **Копия товара и залив — только администраторам**
   (`features.ad_templates_shown`). Рядовому подписчику эти разделы не видны.
4. **Автоматика работает на активном аккаунте**, а не на всех подключённых
   сразу. «Управление несколькими магазинами» — правда только про
   переключение и хранение.
5. **Оплату подписки бот не проверяет** — она идёт вне бота, кнопка так и
   называется «передал владельцу».
6. **Поднятие объявлений тратит деньги продавца** и идёт через панель, а не
   через API: оно зависит от живой сессии панели.
7. **Автовозврат отдаёт деньги покупателю** и по умолчанию выключен.
