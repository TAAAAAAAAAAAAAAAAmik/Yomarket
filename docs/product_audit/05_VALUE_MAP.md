# 05. Карта ценности продукта

Каждая строка: **функция → проблема → что продавец делает вручную → что делает
Юмаркет Менеджер → результат → практическое преимущество → допустимое
маркетинговое сообщение.**

Правило раздела: «допустимое сообщение» — это формулировка, которую **можно
доказать кодом**. Всё, что доказать нельзя, вынесено в «нельзя говорить».

## 1. Автовыдача подарочных карт (13 видов)

| | |
|---|---|
| **Проблема** | заказ оплачен ночью; покупатель ждёт код и уходит в спор |
| **Ручной процесс** | открыть кабинет поставщика → найти номинал → купить → скопировать код → открыть чат заказа на Юмаркете → вставить → проверить, что ушло |
| **Что делает продукт** | замечает оплату (≤60 с), определяет регион из описания объявления, читает каталог поставщика, покупает номинал, дожидается кода (до 120 с), отправляет покупателю в чат заказа, пишет в журнал |
| **Результат** | код у покупателя без участия продавца, круглосуточно |
| **Преимущество** | семь ручных шагов на заказ становятся нулём |
| **Допустимое сообщение** | «Заказ оплачен в три ночи — код у покупателя, пока вы спите» |
| **Нельзя говорить** | «мгновенно» (минута на заказ + до двух минут на код); «мы покупаем коды за вас» (ключ и деньги продавца); «Robux на аккаунт» (выдаётся код) |

**Proof:** `bot/tasks/manager.py:2893`, `:3115`; `bot/automation/giftcards.py`.

## 2. Автоответы покупателю

| | |
|---|---|
| **Проблема** | покупатель пишет и ждёт; продавец спит, ест, работает |
| **Ручной процесс** | держать Telegram открытым, проверять чаты, отвечать одно и то же по десять раз в день |
| **Что делает продукт** | читает «горячие» чаты каждые 10 секунд, подбирает правило по словам письма, отвечает — с паузой между ответами, потолком на заказ и тихими часами |
| **Результат** | покупатель получает ответ, продавец — уведомление |
| **Преимущество** | скорость реакции перестаёт зависеть от того, смотрит ли продавец в телефон |
| **Допустимое сообщение** | «Покупатель написал — ответ ушёл, пока вы не у телефона» |
| **Нельзя говорить** | «мгновенно» (10 с — пол, при замедлении до 120 с); «ИИ отвечает за вас» (подбор по ключевым словам) |

**Proof:** `bot/autoreply.py:150`, `:200`; `bot/tasks/manager.py:4036`.

## 3. Автовосстановление распроданного

| | |
|---|---|
| **Проблема** | товар продан — он ушёл с витрины, и магазин молча перестал продавать |
| **Ручной процесс** | заметить, что продаж нет → зайти в кабинет → найти снятое → опубликовать заново → и так после каждой продажи |
| **Что делает продукт** | возвращает товар в продажу **сразу после покупки** (`instant`), плюс плановый проход раз в час; не публикует распроданное (`require_stock`); отвергнутое маркетплейсом не долбит каждый час |
| **Результат** | витрина не пустеет |
| **Преимущество** | потеря продаж из-за незамеченного снятия закрывается полностью в той части, которую можно вернуть через API |
| **Допустимое сообщение** | «Продали — товар вернулся на витрину сам, в ту же минуту» |
| **Нельзя говорить** | «вернём любой снятый товар»: статус `unpublish` через API не публикуется — такие публикуются на сайте |

**Proof:** `bot/tasks/manager.py:4452`, `:4523`; `bot/api/yoomarket.py:308`.

## 4. Продвижение по позиции в выдаче

| | |
|---|---|
| **Проблема** | объявление съезжает вниз; поднятие по таймеру платит вслепую — и когда товар и так первый, и когда конкурент дешевле и клик всё равно уйдёт к нему |
| **Ручной процесс** | открывать витрину, глазами искать свой товар, решать, платить ли |
| **Что делает продукт** | читает **реальное место** товара на публичной витрине (в API продавца позиции нет), сравнивает с порогом, предупреждает; поднимает — только если это отдельно разрешено |
| **Результат** | деньги на продвижение тратятся тогда, когда позиция правда просела |
| **Преимущество** | четыре предохранителя против слива бюджета: пауза 6 ч, 3 поднятия в сутки, бюджет в рублях, защита от демпинга |
| **Допустимое сообщение** | «Бот смотрит, на каком вы месте, — и не платит, когда платить бессмысленно» |
| **Нельзя говорить** | «гарантируем первое место», «всегда в топе» |

**Proof:** `bot/automation/position.py`; `bot/tasks/manager.py:4269`.

## 5. Остатки, которые перечитываются

| | |
|---|---|
| **Проблема** | «остатки отправлены, а в наличии их нет» — и публикация отказывает `empty_stock` |
| **Ручной процесс** | отправить, поверить ответу, попробовать опубликовать, получить отказ, отправить ещё раз — и положить те же коды дважды |
| **Что делает продукт** | отправляет, **перечитывает** через 0, 3 и 7 секунд, и называет два разных числа: сколько маркетплейс «принял» и сколько реально в списке |
| **Результат** | продавец знает, готов ли товар к публикации, до того как нажмёт «опубликовать» |
| **Преимущество** | кнопки «прислать ещё раз» намеренно нет: она положила бы те же ключи дважды и один код ушёл бы двум покупателям |
| **Допустимое сообщение** | «„Принял" и „в наличии" — разные вещи, и бот их различает» |
| **Нельзя говорить** | «остатки появляются мгновенно» |

**Proof:** `bot/api/yoomarket.py:55`, `:60`, `:88`.

## 6. Статистика из журнала магазина

| | |
|---|---|
| **Проблема** | отчёт говорит, что день пустой, а день таким не был: бот не видел продаж, пока лежал |
| **Ручной процесс** | считать по кабинету маркетплейса вручную |
| **Что делает продукт** | берёт цифры из **журнала операций панели**, а не из того, что успел увидеть; при недоступности панели переходит на локальную историю и **называет источник** |
| **Результат** | выручка не зависит от аптайма бота |
| **Преимущество** | экран статистики и дневной отчёт считаются одним кодом — они не могут разойтись |
| **Допустимое сообщение** | «Цифры берутся из журнала магазина, а не из того, что бот успел заметить» |
| **Нельзя говорить** | «полная аналитика за всё время» без оговорки про сессию панели |

**Proof:** `bot/stats_source.py` (`PANEL`, `LOCAL`, `source_note`).

## 7. Автопилот — один экран на всю автоматику

| | |
|---|---|
| **Проблема** | автоматика разложена по пяти меню, и часть её **молча ничего не делает**, пока не зайдёшь на второй экран и не заполнишь обязательное поле |
| **Ручной процесс** | обойти все меню, вспомнить, что где включено, и не заметить, что включённое не работает |

| **Результат** | продавец видит всю автоматику разом и знает, что из неё правда работает |
| **Преимущество** | четыре готовых набора, включая «🔴 Выключить всё» |
| **Допустимое сообщение** | «Включённое, но неработающее — бот скажет об этом сам» |

## 11. Бот работает на сервере, а не на компьютере продавца

| | |
|---|---|
| **Проблема** | у конкурирующих решений часто нужно держать программу запущенной |
| **Ручной процесс** | не выключать компьютер, следить, что программа жива |
| **Что делает продукт** | все циклы крутятся на сервере; Telegram — только интерфейс |
| **Результат** | автоматика идёт при выключенном телефоне и закрытом Telegram |
| **Преимущество** | доказуемо архитектурой: `TaskManager.start_all()` на старте процесса, задачи на `asyncio`, никакого клиента |
| **Допустимое сообщение** | «Компьютер держать включённым не нужно» |
| **Нельзя говорить** | «работает 24/7 без сбоев» — это обещание аптайма, которого никто не давал |

**Proof:** `bot/main.py:main()`, `bot/tasks/manager.py:1143` (`start_all`).

## 12. Продукт не тратит деньги продавца без разрешения

| | |
|---|---|
| **Проблема** | автоматизация, которая сама платит, — это страх, а не польза |
| **Что делает продукт** | из коробки **наблюдает и сообщает**: включены только уведомления о заказах, сообщениях и жалобах. Все виды платного поднятия, автовозврат и вся автовыдача выключены по умолчанию |
| **Результат** | ничего не тратится и не отдаётся, пока продавец сам не включит |
| **Преимущество** | у платных автоматик отдельные потолки: бюджет в сутки на позицию, денежный потолок расписания, 3 возврата в сутки |
| **Допустимое сообщение** | «Из коробки бот только смотрит и сообщает. Всё, что тратит деньги, включаете вы» |

**Proof:** `bot/storage.py:_DEFAULT_SETTINGS` — сводная таблица значений по
умолчанию в `03_AUTOMATIONS.md`.
