# 04. Пользовательские сценарии

Сценарии составлены по реальному интерфейсу: каждая стрелка — существующая
кнопка, команда или экран. Там, где бот ветвится, ветвление показано, а не
сглажено.

---

## Поток 0. Первый контакт: `/start`

**Экран, говорящий о доступе, сначала смотрит, есть ли он.** Раньше `/start`
ветвился только по токену, и взявший пробу или заплативший снова видел
витрину с «🚀 Получить доступ» — предложение купить то, что у него уже есть.

Состояний три:

```
/start
 ├── магазин на связи (есть токен)         → главное меню
 ├── доступ открыт, магазина нет           → «✅ Доступ открыт, остался один шаг»
 │                                            + кнопка подключения магазина
 └── доступа нет                           → витрина: что бот делает, тарифы,
                                              пробы, поддержка, документы
```

**Proof:** `bot/handlers/start.py` (`cmd_start`, `_no_shop_screen`),
`bot/tests/test_trial_gate.py` (сверяет, что команда и кнопка `menu:main`
показывают один и тот же экран).

**Важно для воронки:** пока переключатель «Требовать подписку» **выключен**,
подключение магазина свободно для всех — бот в этом режиме бесплатный, и это
решение владельца.

## Поток 1. Новый человек берёт бесплатный доступ

```
1. /start                              → витрина
2. «🚀 Получить доступ»                → экран доступа
   Обе пробы стоят прямо здесь, каждая своей кнопкой и с ЧИСЛОМ ДНЕЙ на ней
3a. «Взять 3 дня»                      → доступ открыт сразу
3b. «7 дней за подписку на канал»      → экран со ссылкой на канал
    → подписался → «Проверить»         → проверка getChatMember
       ├── подписан                    → +7 дней
       ├── не подписан                 → отказ, право на пробу НЕ сгорает
       └── спросить не вышло           → +7 дней всё равно, причина в журнал
4. Обе пробы складываются              → 10 дней
```

**Почему кнопка «за подписку» может отсутствовать:** канал не задан владельцем
— подписаться не на что, и проверять нечего. Дохлую кнопку не рисуем.

**Proof:** `bot/handlers/start.py` (`show_access`, `trial_free`, `trial_offer`,
`trial_check`), `bot/trialgate.py`, `bot/storage.py:2174` (`start_trial`).

## Поток 2. Подключение магазина

```
1. «Подключить магазин»                → экран с инструкцией, где взять токен
   (форма ждёт токен и на витрине: кто знает, где его брать,
    вставит не нажимая ничего)
2. Продавец присылает токен            → проверка через GET /shop
   ├── принят                          → имя магазина сохранено, фоновые
   │                                      циклы заведены, главное меню
   └── не принят                       → причина по-русски + «попробовать
                                          снова»; токен запомнен, чтобы не
                                          вводить заново
```

**Кнопка подключения знает про ворота:** при включённой подписке у продавца
без доступа её не показывают вовсе, а экран говорит «сначала открой доступ».
Принять токен и тут же отказать — хуже, чем не просить.

**Proof:** `bot/handlers/start.py` (`start_connect`, `token_help`,
`retry_token`, `_can_connect`), `bot/api/yoomarket.py:231` (`check`),
`bot/tasks/manager.py:1120` (`start_for_user`).

## Поток 4. Настроить автоответы покупателю

```
⚡ Автопилот → «Отвечать на сообщения покупателя» → включить
   └── предупреждение «нет ни одного правила» → «ar:tpl»
        ├── применить готовый шаблон правил
        └── или «➕ Добавить правило»: слова → текст ответа
Тонкая настройка (ar:opts):
   • пауза между ответами в чат       (по умолчанию 30 мин)
   • потолок ответов на заказ         (3)
   • отвечать только вне рабочих часов (выкл; окно 22:00–09:00)
   • отвечать ли на жалобы            (выкл)
Проверка:
   • «🧪 Проверить»   — подобрать правило на пробном тексте
   • «🔍 Почему молчит» — причина дословно
   • «📜 Журнал»      — что ушло, по какому правилу, с каким исходом
```

**Proof:** `bot/handlers/responders.py` (36 экранов `ar:*`),
`bot/autoreply.py:44` (`DEFAULTS`), `:200` (`gate`).

## Поток 5. Настроить автовыдачу подарочных карт

```
1. Главное меню → «🧩 Плагины»
2. Выбрать вид карты (13 в реестре)
3. Экран доступа поставщика:
   ├── вставить ключ AppRoute
   ├── при необходимости «🌐 Прокси» (у поставщика белый список IP,
   │   а адрес сервера меняется при каждом выкате)
   └── «🧪 Годится ли он» — ПРОВЕРЯЕТ прокси: спрашивает адрес трижды
       и сверяет с прямым; ловит и ротацию, и не применившийся прокси
4. «⚙️ Настройки»: регион, слово-опознаватель, текст покупателю, заметка
5. «📦 Наличие и баланс» — что есть у поставщика и на какие деньги
6. «🏷 Создать товар» — объявление на номинал, который у поставщика ЕСТЬ
7. «▶️ Включить»
Дальше:
   заказ оплачен → код куплен → код у покупателя в чате заказа
   → запись в «📜 Журнал выдач»
```

**Proof:** `bot/handlers/plugins.py` (экраны `plugins:gc:*`),
`bot/handlers/approute.py` (`apr:*`), `bot/automation/giftcards.py`.

## Поток 6. Завести товар

```
1. «🚀 Объявления» → «➕ Добавить товар» → «✍️ Создать товар»
2. Название → Цена → Описание → Количество (можно пропустить) → Фото
3. Предпросмотр (любой шаг правится кнопкой «✏️»)
4. «Создать»
   ├── панель приняла  → отчёт с номером + публикация
   └── панель отказала 422
        ├── назвала недостающее поле («Поле Регион обязательно»)
        │    → бот спрашивает ИМЕННО ЭТО поле и досылает товар
        ├── нашла ссылку в описании
        │    → говорит, какие ссылки разрешены (белый список панели)
        └── нашла запрещённое слово
             → убирает его ВМЕСТЕ С ОКОНЧАНИЯМИ, отправляет заново
               и НАЗЫВАЕТ убранное в отчёте (ровно один такой заход)
```

**Предусловие:** подключённая панель продавца (⚙️ Настройки → 🌐 Панель
продавца). Без неё создание не работает вовсе.

**Proof:** `bot/handlers/create_ad.py:222`, `:592`, `:1345`, `:1691`;
`bot/automation/panel.py:3466`, `:3489`, `:3327`, `:3400` (`forbidden_words`).

## Поток 7. Положить остатки

```
Товар → «📦 Прислать остатки» → одно сообщение со списком позиций
  → отправка (POST /ads/{id}/items)
  → маркетплейс отвечает {"status":"ok","accepted":N}   ← это «ВЗЯЛ В РАБОТУ»
  → бот перечитывает через 0, 3 и 7 секунд, пока позиций не хватит
  ├── хватило        → «✅ в наличии N»
  ├── принял N, в списке M → «отправлено, принял N, в списке пока M»
  │                          + кнопка «🔄 Проверить остаток»
  │                          (кнопки «прислать ещё раз» здесь НЕТ намеренно:
  │                           второй такой же список положит те же ключи
  │                           дважды, и один код уйдёт двум покупателям)
  └── не назвал числа и в списке пусто → «в наличии их нет» + ответ дословно
```

**Proof:** `bot/handlers/panel_items.py:752` (`item_stock_save`),
`bot/api/yoomarket.py:60` (`confirm_items`), `:88` (`items_accepted`).

## Поток 9. Продавец покупает подписку

```
1. «🚀 Получить доступ» → «💳 Купить»
2. Выбор срока (показываются только те, у которых ЗАДАНА цена):
   2 недели · 1 месяц · 3 месяца · 6 месяцев · 12 месяцев · Навсегда
3. Выбор способа оплаты (показываются только те, у которых ЗАДАНЫ реквизиты)
4. Экран реквизитов — номер моноширинно, копируется нажатием
5. «Я оплатил» → это ПЕРЕДАЧА ЗАЯВКИ, а не проверка оплаты
   → заявка уходит владельцу в журнал: «🧾 1 месяц · 499 ₽ · СБП»
   → под ней кнопка «✅ Выдать 30 дн.»
6. Владелец проверяет поступление и нажимает кнопку → дни у продавца
```

**Ограничение по потоку:** одна заявка в час на человека. Повтору отвечают
вслух — молчание снаружи неотличимо от сломанной кнопки.

**Proof:** `bot/handlers/subscribe.py`, `bot/handlers/commands.py`
(`paid_claim`, `claim_confirm`), `bot/storage.py:2003` (`PAID_CLAIM_EVERY`).

## Поток 10. Несколько магазинов

```
⚙️ Настройки → «👥 Аккаунты»
  ├── список магазинов, активный отмечен
  ├── «➕ Добавить»: имя → токен
  ├── нажатие на магазин → переключение
```

**Что происходит при переключении:** настройки, куки панели и данные

обслуживаются.**

**Proof:** `bot/handlers/accounts.py`, `bot/storage.py:535` (`_account_key`).

## Поток 11. Что видит продавец, ничего не делая

```

подписка кончилась + 3 дня     → данные удалены (обещано в политике)
```

## Незаконченная форма и команда — сквозной механизм

В боте **93 экрана, ждущих ввода**. Любой из них съел бы пришедшую команду —
и команда молча не сработала бы. Внешний middleware `CommandsEscapeForms`
закрывает незаконченную форму, когда пришла команда, и сверяется **и с
подписями кнопок постоянной клавиатуры** (они приходят обычным текстом).

Говорит об этом вслух он только про **наполовину заполненную** форму. Пустая
закрывается молча — терять в ней нечего. Ожидание токена молчит всегда: его
взводит сам бот, и «↩️ Незаконченная форма закрыта» приходило на каждую
команду подряд, притом что продавец формы не открывал.

**Proof:** `bot/main.py:242` (`CommandsEscapeForms`).
