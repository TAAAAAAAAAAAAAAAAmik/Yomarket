# 02. Каталог функций

Главный документ базы. Здесь перечислены **все пользовательские функции**,
найденные прослеживанием цепочки «кнопка или команда → обработчик → бизнес-
логика → результат».

## Соглашение о глубине карточек

Полная карточка (все поля брифа) заведена на функции уровня **Critical** и
**High** — то есть на те, ради которых продукт покупают. Функции уровня
**Medium** и **Low** описаны сжатой карточкой: статус, место, доступ, что
делает, триггер, ограничения, proof. Это не экономия, а читаемость: полная
карточка на «кнопку смены часового пояса» состоит из пустых полей, и среди
них теряется то, что важно.

## Обозначения

* **Статус** — Production / Beta / Internal / Disabled / Legacy.
* **Доступ** — 👤 любой подписчик · 👑 только администратор · 🔒 скрыто флагом.
* **Ценность** — Critical / High / Medium / Low.
* **MP** — marketing potential, 1–10.

Сквозное условие для всех функций магазина: **нужен подключённый токен**
(`storage.get_token`). Функции, которым нужна ещё и живая сессия панели,
помечены отдельно.

# A. Объявления и товары

## A1. Список объявлений и карточка товара

### Статус
Production

### Где находится
Главное меню → «🚀 Объявления». Команда `/ads`.

### Для кого доступна
👤 Любой подписчик с подключённым магазином.

### Что делает
Показывает товары магазина постранично, с ценой в строке. Нажатие на товар
открывает карточку: название, цена, остаток, статус, кнопки действий.

### Как работает технически
UI `menu:ads` → `handlers/ads.py:ads_menu` → `YooMarketAPI.get_ads(cursor)` →
`GET /ads` → разбор через `orderfields.ad_price` → клавиатура
`keyboards/main.py:ads_list_keyboard`. Листание — `handlers/pager.py`: курсор
остаётся в памяти процесса, в кнопку едет его номер.

### Как пользователь её включает
Ничего включать не нужно. Работает сразу после подключения магазина.

### Настройки
Нет.

### Триггер
Нажатие кнопки или команда.

### Результат
Продавец видит витрину своего магазина, не открывая сайт.

### Какую проблему продавца решает
Проверить товар с телефона, не заходя в кабинет маркетплейса.

### Польза
Быстрый доступ; точка входа во все остальные действия с товаром.

### Экономия
Не измерена. Заявлять цифры нельзя.

### Уровень ценности
Medium — это витрина, а не автоматизация.

### Marketing potential
3 — базовая функция, её ждут по умолчанию. Как отдельный оффер не работает.

### Для сайта
Обычные возможности; в Hero не выносить.

### Для Telegram
Подборка, не отдельный пост.

### Возможный оффер
«Весь магазин — в переписке с ботом».

### Proof
`bot/handlers/ads.py` (`ads_menu`, `paginate_ads`, `show_ad_detail`),
`bot/api/yoomarket.py:234` (`get_ads`), `bot/keyboards/main.py:ads_list_keyboard`,
`bot/handlers/pager.py`.

### Production proof
Обработчик зарегистрирован в роутере `ads.router`, роутер подключён в
`bot/main.py:716`. Кнопка стоит в главном меню (`storage.MENU_BUTTONS`).

### Ограничения
Цена в списке — из объекта `price`, не из карточки; расхождение между списком
и карточкой существует и диагностируется `/order_debug`.

### Запрещённые обещания
Нельзя обещать редактирование цены из списка.

### Риски / нестабильность
Зависит от доступности Integration API и от курсорного листания.

## A2. Создание товара мастером

### Статус
Production

### Где находится
«🚀 Объявления» → «➕ Добавить товар» → «✍️ Создать товар».

### Для кого доступна
👤 Любой подписчик. Нужны **и токен, и сессия панели**: товар создаётся в
панели Nova, публикуется через API.

### Что делает
Пошагово собирает товар — название, цена, описание, количество, фото — и
создаёт его в панели продавца, дозаполняя обязательные поля раздела.

### Как работает технически
UI `create_ad:start` → FSM `CreateAdState` (шаги `title → price → description →
quantity → photo`) → предпросмотр → `create_ad:submit` →
`_panel_create_and_report` → `panel.panel_create_product_sync` (multipart в
Nova) → при отказе 422 читаются недостающие поля (`validation_fields`) и
спрашиваются у продавца (`_ask_for_refused_fields`) → повторная отправка →
остатки через `_fill_stock` → публикация `publish_ad`.

### Как пользователь её включает
1. Подключить магазин (токен).
2. Подключить панель продавца: ⚙️ Настройки → 🌐 Панель продавца → вход по
   email и одноразовому коду.
3. 🚀 Объявления → ➕ Добавить товар → ✍️ Создать товар.

### Настройки
| Параметр | Значения | По умолчанию | Ограничения | Где хранится |
|---|---|---|---|---|
| Название | текст | — | требование панели | FSM состояние |
| Цена | число | — | — | FSM |
| Описание | текст | — | ссылки запрещены, кроме белого списка панели | FSM |
| Количество | число | 1 (кнопка «пропустить») | в форме создания панели поля нет; остаток ставится после создания | FSM |
| Фото | изображение | не обязательно | загружается файлом | FSM |

### Триггер
Действие пользователя.

### Результат
Товар заведён в панели и опубликован; продавец получает отчёт с номером,
списком заполненного и причиной, если что-то не прошло.

### Какую проблему продавца решает
Завести товар с телефона, не разбираясь в форме панели, где обязательность
полей зависит от раздела, а форма об этом молчит.

### Польза
Отказ панели переводится на русский и превращается в вопрос, а не в тупик:
«filter__8: Поле Регион обязательно» становится вопросом про регион.

### Экономия
Число шагов доказуемо: пять экранов вместо формы панели с 22 полями
(живой перечень полей формы создания — 22, `docs/TECH.md` §7.2). Время не
измерялось.

### Уровень ценности
High

### Marketing potential
6 — полезно, но это «ещё один способ сделать то же самое». Сильная часть —
перевод отказов, а она объясняется дольше, чем читается заголовок.

### Для сайта
Ключевые возможности.

### Для Telegram
Отдельный пост — с упором на «бот сам спрашивает то, что потребовала панель».

### Возможный оффер
«Панель отказала — бот объяснил по-русски и спросил недостающее».

### Proof
`bot/handlers/create_ad.py:222` (`create_ad_start`), `:88` (`CreateAdState`),
`:592` (`submit_ad`), `:1691` (`_panel_create_and_report`), `:1345`
(`_ask_for_refused_fields`); `bot/automation/panel.py:3526`
(`panel_create_product_sync`), `:3466` (`validation_fields`), `:3489`
(`explain_validation`), `:3327` (`link_trouble`).

### Production proof
Роутер `create_ad.router` подключён (`bot/main.py:717`). Живые HTTP-тесты
гоняют этот же путь по подставной Nova: `bot/tests/test_ad_copy_live.py`.

### Ограничения
Без сессии панели не работает вовсе. Количество, отправленное в форму
создания, панель игнорирует — остаток проставляется отдельным шагом.

### Запрещённые обещания
Нельзя обещать создание товара «одним нажатием» — это мастер.
Нельзя обещать, что панель примет любое описание: ссылки она запрещает.

### Риски / нестабильность
Сессия панели истекает молча; обязательность полей раздела заранее неизвестна,
и первый заход может закончиться вопросом.

## A3. Копия товара по образцу

### Статус
Production, но **закрыта флагом для рядового пользователя**

### Где находится
«🚀 Объявления» → «➕ Добавить товар» → «📋 Шаблонная копия» (в интерфейсе
переименована в раздел «🌊 Залив»).

### Для кого доступна
👑 Только администратор. Заслон — `features.ad_templates_shown(user_id)`,
который возвращает `is_admin(uid)`. Стоит и на списке, и на самом нажатии, а
не только на кнопке.

### Что делает
Создаёт второй такой же товар одним нажатием: читает у образца раздел,
подраздел, тип выдачи, атрибуты раздела, название, описание, цену, картинку —
и заводит копию тем же путём, что и мастер.

### Как работает технически
`create_ad:copy:{id}` → `copy_item` → `_run_copy` → `_copy_source_values`
(панель: форма правки + карточка + строка списка; маркетплейс: название,
описание, цена, тип выдачи) → очередь списков `_select_queue` → создание →
`_fill_stock` → публикация. Ответы запоминаются за образцом и за разделом
маркетплейса (`storage.get_copy_marks`).

### Как пользователь её включает
Недоступна рядовому пользователю. Администратор: 🚀 Объявления → ➕ Добавить
товар → 📋 Шаблонная копия → выбрать товар.

### Настройки
| Параметр | Значения | По умолчанию | Где хранится |
|---|---|---|---|
| Остатки по умолчанию | список строк | **пусто** | `settings.copy_stock` |
| Память ответов за образцом | номер и надпись раздела/подраздела/типа | заполняется после успеха | `settings.copy_marks` |

### Триггер
Действие пользователя.

### Результат
Готовая копия на витрине с остатком и публикацией; отчёт называет, что бот
заполнил сам, числами.

### Уровень ценности
High для администратора, **нулевая для подписчика** — он её не видит.

### Marketing potential
**1 — рекламировать нельзя.** Функция закрыта флагом.

### Для сайта
Не показывать.

### Для Telegram
Не подходит.

### Proof
`bot/features.py:ad_templates_shown`, `bot/handlers/create_ad.py:2619`
(`copy_item`), `:2674` (`_run_copy`), `:2404` (`_copy_source_values`),
`bot/storage.py:598` (`get_copy_marks`).

### Production proof
Обработчики зарегистрированы и покрыты живыми тестами
(`bot/tests/test_ad_copy_as_panel_answers.py`), но `ad_templates_shown`
отсекает не-администратора на каждом входе.

### Ограничения
Не копирует остатки товара с авто-выдачей (это одноразовые коды — копия
продала бы один код дважды). Не публикует сама, если что-то не перенеслось.

### Запрещённые обещания
Не обещать эту функцию подписчикам вообще, пока флаг не снят.

## A4. Залив — копии по расписанию

### Статус
Production, **закрыт флагом для рядового пользователя**

### Где находится
Главное меню → «🌊 Залив» (кнопка появляется только тем, кому раздел открыт).

### Для кого доступна
👑 Только администратор (`features.ad_templates_shown`, тот же флаг, что у A3).

### Что делает
Раз в заданное число минут заводит копии отмеченных товаров и удаляет
вчерашние собственные копии. Это автоматизация приёма, которым продавцы
поднимают объявление наверх выдачи вручную: завести такое же заново, старое
удалить.

### Как работает технически
`_tick` (раз в минуту) → `TaskManager._maybe_pour` → проверка окна часов,
шага, суточного потолка → круговая очередь, не больше `_POUR_PER_PASS = 5`
товаров за проход → `create_ad.pour_once` → тот же `_run_copy`, но с
подставным сообщением `_Quiet` и состоянием `_MemState({"silent": True})` →
номер созданного пишется в `pour.made` → `_pour_delete` удаляет вчерашние.

Вопрос, на который в тихом режиме некому ответить, превращается в пропуск с
причиной: `_ask_next_select` пишет `silent_stop=<поле>` и выходит.

### Настройки
| Параметр | Значения | По умолчанию | Ограничения | Где хранится |
|---|---|---|---|---|
| `enabled` | вкл/выкл | выкл | — | `settings.pour.enabled` |
| `every` | минуты | 1 | минимум 1 — общий проход и так раз в минуту | `pour.every` |
| `items` | список товаров | пусто | выбор страницами по 12 | `pour.items` |
| `from_hour`/`to_hour` | 0–24 | 0–24 | считается по часам продавца, работает через полночь; совпавшие границы = круглосуточно | `pour.from_hour`, `pour.to_hour` |
| `cap` | копий на товар в сутки | 0 (без потолка) | сутки продавца; в журнале говорится один раз за сутки | `pour.cap` |
| `keep` | сколько копий держать | 0 | удаляет лишние и сегодняшние | `pour.keep` |
| `gap` | пауза между товарами, с | 0 | — | `pour.gap` |
| `publish` | публиковать сразу | да | — | `pour.publish` |
| `stock` | остатки на каждый товар | пусто | до 200 строк на товар | `pour.stock[ad_id]` |

### Триггер
Таймер: общий проход `_tick`, раз в минуту, с проверкой собственного шага.

### Результат
Копии заводятся и удаляются сами; каждый отказ записывается в журнал
(`pour.log`, последние 30 записей).

### Уровень ценности
High для администратора, **нулевая для подписчика**.

### Marketing potential
**1 — рекламировать нельзя** при нынешнем флаге. Отдельно: минутный залив даёт
около 1440 объявлений в сутки на товар, на что маркетплейс может ответить
ограничением — экран об этом говорит прямо.

### Для сайта / Telegram
Не показывать / не подходит.

### Proof
`bot/handlers/create_ad.py:2573` (`pour_once`), `:3009`–`:3483` (экраны
`pour:*`), `bot/tasks/manager.py:1366` (`_maybe_pour`), `:1517`
(`_pour_delete`), `bot/storage.py:700` (`get_pour`).

### Production proof
`_maybe_pour` вызывается из `_tick` (`bot/tasks/manager.py:1360`) — то есть
фоновым циклом, а не только по кнопке. Покрыт `bot/tests/test_pour.py`.

### Ограничения
Удаляет **только свои** копии — те, чьи номера записал за собой. Не больше 5
товаров за проход. Не спрашивает — упирается в вопрос и пропускает товар с
причиной.

### Запрещённые обещания
Не обещать «бесконечное поднятие в топ»: это создание новых объявлений, и
реакция маркетплейса на минутный темп не проверена.

### Риски / нестабильность
Зависит от панели и от лимитов маркетплейса; удаление необратимо.

## A5. Остатки товара

### Статус
Production

### Где находится
Карточка товара панели → «📦 Прислать остатки», «🔄 Проверить остаток».

### Для кого доступна
👤 Любой подписчик.

### Что делает
Принимает список позиций одним сообщением и кладёт их в товар; затем
перечитывает и говорит, сколько реально в наличии.

### Как работает технически
`pitem_stock:{id}` → `item_stock_start` → FSM ждёт сообщение →
`item_stock_save` → `YooMarketAPI.add_ad_items` → `POST /ads/{id}/items` →
ответ `{"status":"ok","accepted":N}` → `items_accepted` разбирает N →
`confirm_items` перечитывает по паузам `(0, 3, 7)` секунд, пока позиций не
станет достаточно → `orderfields.ad_items_free` считает свободные.

### Триггер
Действие пользователя.

### Результат
Отчёт вида «отправлено, принял N, в списке пока M» — и кнопка «🔄 Проверить
остаток». Кнопки «прислать ещё раз» там нет намеренно: второй такой же список
положил бы те же ключи дважды, и один код ушёл бы двум покупателям.

### Какую проблему продавца решает
«Остатки отправлены, а в наличии их нет». Маркетплейс отвечает «принял»
раньше, чем кладёт позиции; немедленная проверка объявляла успешную отправку
неудачей.

### Уровень ценности
Critical — без остатка товар не публикуется (`empty_stock`).

### Marketing potential
7 — конкретная, доказуемая честность: бот не говорит «готово» там, где
маркетплейс ещё не положил.

### Для сайта
Ключевые возможности (в блоке «бот не врёт»).

### Для Telegram
Отдельный пост — кейс с реальным ответом маркетплейса.

### Возможный оффер
«„Принял" и „в наличии" — разные вещи, и бот их различает».

### Proof
`bot/handlers/panel_items.py:728` (`item_stock_start`), `:752`
(`item_stock_save`), `bot/api/yoomarket.py:55` (`_CONFIRM_WAITS`), `:60`
(`confirm_items`), `:88` (`items_accepted`), `bot/orderfields.py:225`
(`ad_items_free`).

### Production proof
Обработчик зарегистрирован (`panel_items.router`, `bot/main.py:718`);
`confirm_items` вызывается и из копии (`_put_items`), и из ручного экрана.

### Ограничения
Придумать остатки бот не может: у товара с авто-выдачей остаток — это сами
коды.

### Запрещённые обещания
Не обещать мгновенное появление позиций: маркетплейс кладёт их с задержкой.

## A6. Товары панели: показать, скрыть, удалить, переименовать

### Статус
Production · 👤 · нужна сессия панели

**Что делает:** список товаров панели по разделам, публикация скрытого
(в том числе «опубликовать все скрытые»), скрытие, удаление с подтверждением,
правка названия, пересчёт остатка.
**Триггер:** действие пользователя.
**Результат:** статус товара перечитывается после действия — «HTTP 200» за
доказательство не принимается.
**Ограничения:** товар со статусом `unpublish` через API не публикуется —
маркетплейс запрос принимает, статус не меняет; такие публикуются на сайте.
Публикация идёт через API, панель — запасной путь, и при отказе обеих
называются **обе** причины.
**Proof:** `bot/handlers/panel_items.py` (`list_items`, `item_show`,
`item_hide`, `publish_all_hidden`, `item_delete_confirm`, `edit_title_start`,
`item_stock_recount`), `bot/api/yoomarket.py:754` (`publish_ad`), `:308`
(`_MANUAL_ONLY`), `bot/automation/panel.py:1389` (`panel_publish_item_sync`).
**Ценность:** High · **MP:** 5 · **Для сайта:** обычные возможности.

## A7. Паки объявлений

## C4. Автоответы покупателю по правилам

### Статус
Production · 👤 · по умолчанию выключено

### Где находится
💬 Чаты → автоответы, либо ⚡ Автопилот → «Отвечать на сообщения покупателя».
Экран `ar:menu`.

### Что делает
Отвечает покупателю сам: подбирает правило по словам из письма, шлёт ответ,
соблюдает паузу между ответами, потолок ответов на заказ, тихие часы и
отдельное решение о жалобах.

### Как работает технически
`_chat_tick` (раз в 10 с) → `_check_messages` → на каждое новое письмо
`autoreply.pick(conf, text)` подбирает правило → `autoreply.gate(conf,
chat_id)` решает, можно ли сейчас → `_send_chat` → ответ маркетплейса
разбирает `autoreply.explain_error` → запись в журнал `autoreply.log`.

### Настройки
| Параметр | Значения | По умолчанию | Смысл | Где хранится |
|---|---|---|---|---|
| `enabled` | вкл/выкл | **выкл** | — | `autoreplies.enabled` |
| `rules` | список правил `{keywords, text, on, weak}` | пусто | есть готовые шаблоны (`ar:tpl`) | `autoreplies.rules` |
| `fallback` | `{on, text}` | выкл, текст задан | ответ, когда не подошло ни одно правило | `autoreplies.fallback` |
| `cooldown_min` | минуты | **30** | не чаще одного автоответа в чат | `autoreplies.cooldown_min` |
| `max_per_order` | число | **3** | и не больше N на один заказ | `autoreplies.max_per_order` |
| `quiet_only` | вкл/выкл | выкл | отвечать только вне рабочего времени | `autoreplies.quiet_only` |
| `from_hour` / `to_hour` | часы | **22 / 9** | окно «нерабочего» времени | там же |
| `reply_to_complaints` | вкл/выкл | **выкл** | отвечать ли на жалобы автоматически | там же |

### Триггер
Входящее сообщение покупателя, замеченное опросом чатов.

### Результат
Покупатель получает ответ в пределах десяти секунд от письма (для «горячих»
чатов). Продавец видит журнал: что ушло, по какому правилу, с каким исходом.

### Отдельная функция внутри: «🔍 Почему молчит»
Экран `ar:why` называет причину молчания дословно: «автоответы выключены»,
«сейчас рабочее время — отвечаю только с 22:00 до 09:00», «пауза между
ответами — ещё 12 мин», «по этому заказу уже 3 автоответа — дальше вручную».
Причина возвращается **всегда**, даже когда «можно» — чтобы продавец видел, а
не гадал.

### Какую проблему продавца решает
Покупатель пишет ночью и уходит, не дождавшись. Продавец не может сидеть в
переписке круглосуточно.

### Польза
Ответ уходит без человека, но не превращается в спам: пауза и потолок стоят
по умолчанию, а не «если настроишь».

### Экономия
Скорость реакции доказуема архитектурно: «горячий» чат читается каждые 10
секунд против «раз в минуту» в прежней версии. Число сэкономленных часов не
измерялось — не заявлять.

### Уровень ценности
Critical

### Marketing potential
9 — понятная боль, мгновенно объяснимая польза, есть честная деталь про
паузы и лимиты, которая отличает продукт от спам-рассылки.

### Для сайта
Hero-кандидат либо первый блок ключевых возможностей.

### Для Telegram
Отдельный большой пост + кейс + отдельный пост про «почему молчит».

### Возможный оффер
«Покупатель написал ночью — ответ ушёл за десять секунд, а не утром».

### Proof
`bot/autoreply.py:44` (`DEFAULTS`), `:150` (`pick`), `:200` (`gate`),
`:256` (`explain_error`), `:282` (`log`); `bot/handlers/responders.py`
(экраны `ar:*`, 36 обработчиков); `bot/tasks/manager.py:4036` (`_auto_answer`),
`:2070` (`_check_messages`).

### Production proof
Вызывается из `_chat_tick` → `_check_messages` (`bot/tasks/manager.py:1312`),
то есть фоновым циклом каждые 10 секунд. Голос покупателя защищён тестом
`bot/tests/test_voice.py`.

### Ограничения
Не отвечает в закрытый чат (маркетплейс не пускает). По умолчанию не отвечает
на жалобы. Опрос замедляется, если маркетплейс просит сбавить темп.

### Запрещённые обещания
Не обещать «мгновенный ответ»: 10 секунд — это пол опроса, а при замедлении
интервал растёт до 120 секунд. Не обещать «искусственный интеллект отвечает
за вас» — подбор идёт по ключевым словам, а не моделью.

### Риски / нестабильность
Зависит от polling и от лимитов маркетплейса (нигде не опубликованных). При
`too_many_requests` темп падает вдвое, до потолка 120 секунд, и замедление
показывается на экране «почему молчит», а не скрывается.

# F. Автовыдача и поставщики

## F1. Автовыдача подарочных карт — 13 видов

### Статус
Production · 👤 · каждая карта включается отдельно, все по умолчанию выключены

### Где находится
Главное меню → «🧩 Плагины» → карточка вида.

### Для кого доступна
👤 Любой подписчик. Нужен **свой ключ поставщика** — деньги тратятся со счёта
продавца, не продукта.

### Что делает
По факту оплаты заказа покупает код у поставщика и отправляет его покупателю
в чат заказа. Продавец не участвует.

Виды в реестре (13): Roblox Gift Cards, Apple, PlayStation Store, Xbox, Steam,
Amazon, Razer Gold, Airbnb, Eneba, Twitch, Meta Quest, Battle.net, OZON.ru.

### Как работает технически
`_tick` → `_process_orders` → новый оплаченный заказ → `_maybe_deliver_gifts`
→ `_maybe_deliver_gift` → определение региона из описания объявления
(`_gift_region_of`, `region_from_description`) → каталог поставщика
(`_supplier_catalog`, кеш на пару минут) → покупка через
`automation/approute.py` → ожидание кода `_gift_wait_codes` (шаги
12…60 с, потолок `_GIFT_POLL_CEILING = 120` с) → `_gift_finish` → отправка
покупателю → запись в журнал. Недоведённую выдачу подбирает `_gift_resume`,
принудительный обход — `_gift_forced_sweep`.

### Как пользователь её включает
1. 🧩 Плагины → выбрать карту.
2. Задать ключ поставщика (AppRoute) на экране доступа, при необходимости —
   прокси с постоянным адресом.
3. Указать регион и слово-опознаватель, если нужно.
4. «▶️ Включить».

### Настройки на каждую карту
| Параметр | Значения | По умолчанию | Смысл | Где хранится |
|---|---|---|---|---|
| `enabled` | вкл/выкл | **выкл** | — | `plugins.auto_gifts` / реестр карт |
| регион | код региона | зависит от карты | глобальный и российский коды невзаимозаменяемы | настройки карты |
| слово-опознаватель | текст | пусто | пусто = все обычные написания | там же |
| приветствие / заметка | текст | заготовка | голос **магазина**, обращён к покупателю на «вы» | там же |
| название и описание товара | шаблон | заготовка с `{номинал}`, `{регион}` | для кнопки «🏷 Создать товар» | там же |

### Триггер
Оплата заказа, замеченная проходом `_process_orders` (раз в минуту).

### Результат
Покупатель получает код в чат заказа. Продавец видит запись в журнале выдач:
что, кому, почём.

### Какую проблему продавца решает
Заказ приходит ночью, покупатель ждёт код, продавец спит. Либо продавец сидит
у телефона и выдаёт руками каждый заказ.

### Польза
Выдача идёт круглосуточно и не зависит от того, открыт ли Telegram.

### Экономия
Ручных действий на заказ: было — открыть кабинет поставщика, купить код,
скопировать, открыть чат заказа, вставить; стало — ноль. Время не измерялось.

### Уровень ценности
Critical — это главная причина покупать продукт.

### Marketing potential
10 — очевидная боль, мгновенный результат, 13 узнаваемых брендов.

### Для сайта
**Hero-кандидат номер один** и отдельный блок.

### Для Telegram
Отдельный большой пост, кейс, подборка «13 карт», серия по видам.

### Возможный оффер
«Заказ оплачен в 3 ночи — код у покупателя через минуту».

### Proof
`bot/automation/giftcards.py` (реестр, 13 записей `slug=`/`title=`),
`bot/tasks/manager.py:2893` (`_maybe_deliver_gifts`), `:2920`
(`_maybe_deliver_gift`), `:3073` (`_gift_wait_codes`), `:3115`
(`_gift_finish`), `:3321` (`_gift_resume`), `:3274` (`_gift_forced_sweep`);
`bot/handlers/plugins.py` (экраны `plugins:gc:*`).

### Production proof
`_maybe_deliver_gifts` вызывается из `_process_orders`
(`bot/tasks/manager.py:1874` и `:1942`) — фоновым циклом, раз в минуту, а не
только по кнопке. Ручная выдача есть отдельно (`plugins:gc:*:manual`).

### Ограничения
* Нужен **свой** ключ поставщика и деньги на его счёте.
* У поставщика **белый список IP**, а бот живёт там, где адрес меняется при
  выкате — лечится прокси с постоянным адресом.
* Право `orders:write` на ключе — это не «запись», а выдача кодов: без него
  ключ покупает, но кода не отдаёт. Деньги списаны, выдать нечего.
* Ожидание кода ограничено 120 секундами; незавершённое подбирается позже.
* Прямого пополнения аккаунта для Roblox у поставщика нет — только коды.

### Запрещённые обещания
* Не обещать «мы покупаем коды за вас» — ключ и деньги продавца.
* Не обещать «Robux на аккаунт» — выдаётся код, активирует покупатель сам.
* Не обещать выдачу «мгновенно»: заказ замечается раз в минуту, код
  поставщик может отдавать до двух минут.

### Риски / нестабильность
Зависит от внешнего API поставщика, от белого списка IP, от прокси, от
лимитов (`GET /orders` — 2 запроса в минуту) и от наличия номинала в
каталоге.

## G4. Продвижение по позиции в выдаче

### Что делает
Смотрит на **реальное место** товара в списке предложений на публичной витрине

| Порог | Вопрос | По умолчанию |

| `min_price` | когда кричать: рыночная цена упала ниже осмысленной | 0 |

### Предохранители — их четыре, и каждый про деньги
`cooldown_hours` (6) — пауза между поднятиями одного товара;
`daily_limit` (3) — потолок поднятий в сутки;

позиции; `auto_promote` (**выключено**) — по умолчанию бот только
предупреждает, потому что поднятие тратит деньги и решение тратить их
автоматически должно быть осознанным.

У наблюдения **два разных номера** товара, и путать их нельзя: `market_id` с
публичной страницы узнаёт нашу строку среди предложений, `item_id` — запись
панели, к которой обращается платное действие «Премиум». Поднятие по номеру
витрины отвечает 404.

**Proof:** `bot/automation/position.py` (`watches`, `daily_budget`,

## J4. Пробный период — две пробы, и они складываются

### Статус
Production · 👤

### Что делает
Даёт бесплатный доступ двумя независимыми пробами:
* **3 дня без условий** (`TRIAL_FREE_DAYS_DEFAULT = 3`);
* **7 дней за подписку на канал** (`TRIAL_DAYS_DEFAULT = 7`), канал задаёт
  владелец в админке.

Обе берутся по одному разу каждая, **вместе десять дней**: `grant_subscription`
прибавляет к остатку, а не заменяет его. Отметок тоже две (`trials` и
`trials_channel`) — общая означала бы «взял три дня — семь уже не дадут».

### Три исхода проверки подписки на канал, а не два
`getChatMember` отвечает «подписан», «не подписан» — и **«спросить не вышло»**.
Третий случай нельзя выдавать за отказ: бот не админ канала, канал переехал,
вписан не тот адрес — всё это наши поломки, а выглядят они как «ты не
подписан». Поэтому при сорвавшейся проверке проба **выдаётся**, а причина
уходит в журнал: одна неполученная подписка дешевле потерянного клиента.

### Отказ не сжигает право на пробу
Отметка «уже брал» ставится только вместе с настоящей выдачей.

### Ограничения
Поверх **оплаченной** подписки пробы не выдаются (`paid_now`). Отказ при этом
называет свою причину: «у тебя уже есть доступ, осталось N дн.», «пробный
период выключен», «эти дни уже брали» — это три разные беды.

**Proof:** `bot/trialgate.py`, `bot/storage.py:2174` (`start_trial`), `:2083`
(`TRIAL_FREE_DAYS_DEFAULT`), `:1841` (`TRIAL_DAYS_DEFAULT`), `:1132`
(`grant_subscription`); `bot/handlers/start.py` (`trial_offer`, `trial_free`,
`trial_check`); `bot/tests/test_trial_gate.py`.
**Ценность:** Critical для воронки · **MP:** 9 — «10 дней бесплатно» это
конверсионный оффер, и он доказуем.
**Для сайта:** Hero-CTA.
**Запрещённые обещания:** не писать «7 дней бесплатно» — это половина правды;
не писать «10 дней всем» — вторые семь дней за подписку на канал.

## J5. Покупка подписки внутри бота

### Статус
Production · 👤

### Что делает
Проводит покупку целиком в боте: срок → способ оплаты → реквизиты → «я
оплатил». Прежний путь («Прошу счёт», ждите, с вами свяжутся) терял половину
людей.

### Тарифы (`PRICE_TIERS`, 6 сроков)
2 недели · 1 месяц · 3 месяца · 6 месяцев · 12 месяцев · Навсегда.
Цена за срок, которого нет в списке, не показывается никому. «Навсегда»
реализовано как `LIFETIME_DAYS = 36500` — очень большой срок, а не особый
случай.

### Что бот НЕ делает
**Не проверяет оплату.** Оплата идёт вне бота, увидеть её он не может.
Кнопка так и называется — «передал владельцу». Обещание «проверяю оплату»
отправило бы человека ждать того, чего не будет.

### Подтверждение полуавтоматическое
Под заявкой в журнале владельца стоит «✅ Выдать N дн.» — одно нажатие, и дни
уходят ровно тому, кто платил, в том количестве, за которое платил. Отметка
«решена» проверяется **до** выдачи: нажимают дважды именно тогда, когда не
поняли, сработало ли.

### Защита от потока
Заявка ограничена одной в час **на человека** (`PAID_CLAIM_EVERY = 3600`).
Общий счётчик закрыл бы кнопку всем, кто нажал следом. Повтору отвечают
вслух — молчание снаружи неотличимо от сломанной кнопки.

### Интерфейс
Реквизиты — моноширинно, копируются нажатием (`ui.copyable`), и обёрнут
**ровно** номер: `<code>` вокруг всего текста скопировал бы вместе с картой и
«в комментарии — свой ник».

**Proof:** `bot/handlers/subscribe.py` (`choose_term`, `choose_method`,
`show_details`), `bot/handlers/commands.py` (`paid_claim`, `claim_confirm`,
`claim_reject`), `bot/storage.py:1795` (`PRICE_TIERS`), `:2003`
(`PAID_CLAIM_EVERY`), `:2014` (`add_claim`), `:2037` (`settle_claim`),
`bot/ui.py:99` (`copyable`); `bot/tests/test_pricing.py`.
**Ценность:** Critical · **MP:** 5 (это касса, а не возможность продукта).
**Запрещённые обещания:** «автоматическая активация после оплаты»,
«приём платежей в боте».

# M. Скрытое, internal и legacy

## M1. AutoStars — автовыдача Telegram Stars

### Статус
**Disabled (скрыто флагом)** · 🔒

### Почему скрыто
Покупка на Fragment доведена не до конца, и показывать продавцу то, что может
не сработать **с его TON**, нельзя.

### Как именно скрыто
Один переключатель на весь бот — `features.STARS_HIDDEN = True`. Разложенный
по местам («тут не покажем, там не пустим»), он однажды не сошёлся бы сам с
собой, и разойтись это могло бы молча.

Уходят **разом**: кнопка на экране плагинов, строка про звёзды в его тексте,
`/stars` и вся диагностика Fragment из `commandlist`, строка в приветствии,
прокси на экране «Мои прокси», и фоновая выдача.

**Кнопка из старого сообщения — тоже вход.** Заслон стоит один на все нажатия
раздела (`_stars_gate`, middleware роутера), а не проверкой в каждом из
двадцати обработчиков.

### Что это значит для маркетинга
**Функции для подписчика не существует.** Упоминать её нельзя ни в каком виде
— ни как «скоро», ни как «в разработке», пока владелец не решит иначе.

**Proof:** `bot/features.py:STARS_HIDDEN`, `stars_shown`;
`bot/handlers/plugins.py:325` (`_stars_gate`), `:346` (регистрация
middleware); `bot/commandlist.py` (`_STARS_OWN`);
`bot/tasks/manager.py:3434`, `:3472` (гейт внутри фоновых точек входа).
**MP:** 0.

## M3. Legacy naming: `auto_withdraw`

Ключ настроек называется `auto_withdraw`, но автовывода нет: деньги переводит
человек. Имя оставлено намеренно — чтобы у тех, кто уже заполнил реквизиты,
они не пропали. **В документации и текстах называть это «реквизитами вывода»,
а не автовыводом.**
**Proof:** `bot/storage.py` (`_DEFAULT_SETTINGS["auto_withdraw"]` с
комментарием «Автовывода нет»).

## M5. Legacy: простые автоответы

`auto_reply`, `auto_events`, `auto_rules` — прежний механизм ответов, до
`autoreplies` с правилами, паузами и лимитами. Оба живы и оба настраиваются:
`auto_reply` отвечает на **событие заказа**, `autoreplies` — на **письмо
покупателя**. Это не дубль, но объяснять разницу в маркетинге дорого; для
пользователя точка входа одна — ⚡ Автопилот.

---

## M6. Удалённые методы — за ними следит тест

`bump_ad`, `bump_all_ads`, `withdraw_balance`, `get_reviews` были удалены из
клиента Integration API: этих возможностей в API нет вовсе.
`bot/tests/test_dead_buttons.py` падает, если они вернутся. Это существенно
для маркетинга: **соответствующие обещания невозможно выполнить через API**, и
всё перечисленное идёт через панель.
