# 08. Система подачи функций

Каждая функция из `02_FEATURE_CATALOG.md` отнесена к одному из четырёх уровней
подачи.

| Tier | Что означает | Где живёт |
|---|---|---|
| **A** | отдельный крупный блок сайта | Hero, блоки Б-5, Б-6, Б-7 |
| **B** | карточка внутри блока | Б-5 «Возможности» |
| **C** | строка в перечне возможностей | подробная страница, список |
| **D** | только FAQ и документация | `13_FAQ_SOURCE.md`, справка |
| **—** | **не продаётся вообще** | см. `33` в конце документа |

Для Tier A и Tier B дана полная раскладка: pain → feature → mechanism →
benefit → deeper benefit → proof → screenshot → уместность CTA.

---

# TIER A — отдельные блоки сайта

## A-I. Автовыдача подарочных карт и Robux (F1, F2, F5)

**Pain.** Заказ оплачен ночью. Покупатель ждёт код, уходит в спор, а продавец
спит. Днём — то же самое, только вместо сна работа или дорога.

**Feature.** Автоматическая выдача 13 видов подарочных карт и Robux по факту
оплаты.

**Mechanism.** Проход по заказам раз в минуту замечает оплату → регион берётся
из описания объявления → читается каталог поставщика → покупается номинал →
бот дожидается кода (до 120 секунд) → код уходит в чат заказа → запись в
журнал выдач. Оборвавшаяся выдача подбирается следующими проходами.

**Benefit.** Покупатель получает код без продавца, круглосуточно.

**Deeper benefit.** Продавец перестаёт быть обязательным звеном: заказы можно
принимать тогда, когда их удобно делать покупателю, а не тогда, когда удобно
продавцу.

**Proof.** 13 видов перечислены поимённо; журнал выдач показывает, что и почём
ушло; поставщик называет `traceId`, по которому находит запрос у себя.

**Screenshot.** S-01 — GIF «заказ → код в чате» (главный материал сайта);
S-03 — экран плагинов со списком; S-15 — журнал выдач.

**CTA.** Высокой готовности: «Открыть бота» / «Попробовать бесплатно».

**Обязательная оговорка.** Нужен свой ключ поставщика с правом `orders:write`
и деньги на его счёте. Скорее всего — прокси с постоянным адресом.

## A-II. Автовосстановление товара (G5)

**Pain.** Товар продан и снят с витрины. Продаж по нему больше нет. Причина
невидима: продавец видит тишину, а не снятый товар.

**Feature.** Возврат товара в продажу — сразу после покупки и плановым
проходом.

**Mechanism.** Продажа замечается проходом по заказам → товар публикуется
заново в тот же проход (`instant`) → раз в час идёт общий обход → распроданное
не публикуется → отвергнутое маркетплейсом не долбится каждый час.

**Benefit.** Витрина не пустеет.

**Deeper benefit.** Падение продаж перестаёт иметь невидимую причину — одной
неизвестной в бизнесе меньше.

**Proof.** Настройки видны на экране: «возвращать сразу после продажи» и «не
публиковать распроданное».

**Screenshot.** S-11.

**CTA.** Средней готовности: «Посмотреть, как это работает».

**Обязательная оговорка.** Товар со статусом `unpublish` через API не
публикуется — такие публикуются на сайте маркетплейса.

## A-III. Ответы покупателю (C4, C1, H1)

**Pain.** Первый вопрос покупателя решает, купит он или уйдёт. Продавец не
может сидеть в переписке круглосуточно, а одинаковые вопросы приходят по
десять раз в день.

**Feature.** Автоответы по правилам с паузами, потолками и тихими часами.

**Mechanism.** Чаты, где покупатель уже ждёт ответа или заказ моложе двух
часов, читаются каждые 10 секунд → правило подбирается по словам письма →
ответ уходит, если позволяют пауза (30 минут) и потолок (3 ответа на заказ) →
результат пишется в журнал. Отказ маркетплейса переводится на русский вместе с
признаком «можно ли исправить вручную».

**Benefit.** Покупатель получает ответ за секунды, а не за часы.

**Deeper benefit.** Скорость магазина перестаёт зависеть от того, смотрит ли
владелец в телефон.

**Proof.** Экран «🔍 Почему молчит» называет причину дословно; журнал
показывает, что ушло и по какому правилу.

**Screenshot.** S-10 настройки; S-05 «почему молчит».

**CTA.** Средней готовности.

**Обязательная оговорка.** 10 секунд — это пол; при замедлении интервал растёт
до двух минут, и бот это показывает. Подбор идёт по ключевым словам, не
моделью.

## A-IV. Продвижение по позиции (G4, G2, E3)

**Pain.** Поднятие по таймеру платит одинаково и когда товар первый, и когда
конкурент дешевле на треть — и клик всё равно уйдёт к нему.

**Feature.** Слежение за реальным местом товара в списке предложений.

**Mechanism.** Позиции нет в API продавца — бот читает публичную витрину,
находит свою строку и сравнивает с порогом. Три порога отвечают на три разных
вопроса: когда действовать, когда **не платить**, когда предупредить. Четыре
предохранителя: пауза 6 часов на товар, 3 поднятия в сутки, бюджет в рублях,
защита от демпинга. По умолчанию бот только предупреждает.

**Benefit.** Деньги тратятся, когда позиция правда просела.

**Deeper benefit.** Расход на продвижение перестаёт быть чёрным ящиком: видно,
сколько ушло и на что.

**Proof.** Карточка наблюдения с порогами; экран трат на поднятие.

**Screenshot.** S-09 карточка наблюдения.

**CTA.** Средней готовности.

**Запрещено.** «Гарантируем первое место», «всегда в топе».

## A-V. Автопилот (I1)

**Pain.** Автоматика разложена по меню, часть её молча ничего не делает, пока
не заполнишь обязательное поле на другом экране. Продавец не знает, что из
включённого работает.

**Feature.** Один экран на всю автоматику: 18 переключателей, четыре набора.

**Mechanism.** Список по группам → включение в одно нажатие дописывает
разумные значения → у включённой, но неработающей автоматики стоит
предупреждение с кнопкой, ведущей **туда, где чинится** (тариф — на экран
тарифа, а не на экран автоматики) → автоматики, которые тратят деньги,
помечены.

**Benefit.** Настройка перестаёт быть проектом.

**Deeper benefit.** Включённое либо работает, либо само объясняет, почему нет.

**Proof.** Скриншот экрана — он и есть доказательство.

**Screenshot.** S-02 (два кадра со стыком).

**CTA.** Средней готовности.

**Запрещено.** «Настройка в один клик» — предупреждения ведут на вторые
экраны.

## A-VI. Статистика из журнала магазина (E1, E4, E3)

**Pain.** Отчёт показывает пустой день, который пустым не был: бот не видел
продаж, пока лежал.

**Feature.** Выручка, заказы, топ товаров, часы, повторные покупатели, экспорт.

**Mechanism.** Источник — журнал операций панели, а не наблюдения бота. При
недоступности панели бот переходит на локальную историю и **называет
источник**. Экран статистики и дневной отчёт считаются одним кодом.

**Benefit.** Цифры не зависят от аптайма бота.

**Deeper benefit.** На учёт можно опереться при решениях.

**Proof.** Подпись источника прямо на экране.

**Screenshot.** S-07.

**CTA.** Низкой готовности: «Посмотреть возможности».

**Обязательная оговорка.** Журнал читается через панель продавца.

# TIER B — карточки

## B-1. Остатки с перечитыванием (A5)

**Pain.** «Остатки отправлены, а их нет» — и публикация отказывает.
**Feature.** Отправка с проверкой результата.
**Mechanism.** Отправили → маркетплейс ответил «принял N» → бот перечитывает
через 0, 3 и 7 секунд → называет два числа.
**Benefit.** Видно, готов ли товар к публикации.
**Deeper benefit.** Исключён случай, когда один код уходит двум покупателям:
кнопки «прислать ещё раз» рядом нет намеренно.
**Proof / Screenshot.** S-04 — отчёт с двумя числами.
**CTA.** Низкой готовности. Карточка работает на доверие, не на действие.

## B-2. Уведомления о заказах, письмах и спорах (H1, C7)

**Pain.** Заказ пришёл, а продавец узнал через час. Спор начался, а он не
заметил.
**Feature.** Уведомления, включённые **по умолчанию**.
**Mechanism.** Проход по заказам раз в минуту, по горячим чатам — раз в
10 секунд; жалоба распознаётся по словам письма и помечается отдельно.
**Benefit.** Ничего не теряется.
**Deeper benefit.** Это работает **сразу после подключения токена** — первое
подтверждение ценности в тот же день.
**Proof / Screenshot.** S-23 уведомление о жалобе.
**CTA.** Высокой готовности — это самый дешёвый вход в продукт.

## B-3. Мастер создания товара (A2)

**Pain.** Форма панели: 22 поля, обязательность зависит от раздела, отказ
приходит на последнем шаге кодом ошибки.
**Feature.** Пять экранов вместо формы, с переводом отказов.
**Mechanism.** Название → цена → описание → количество → фото →
предпросмотр → отправка. Панель отказала и назвала поле — бот спрашивает
именно его и досылает товар. Запрещённое слово убирает сам, ровно один раз, и
**называет** убранное.
**Benefit.** Отказ становится вопросом, а не тупиком.
**Deeper benefit.** Товары можно заводить с телефона, не разбираясь в панели.
**Proof / Screenshot.** S-13 дозапрос поля.
**CTA.** Средней готовности.
**Оговорка.** Нужна подключённая панель продавца; ссылки в описании панель
запрещает, кроме белого списка.

## B-4. Несколько магазинов (J1)

**Pain.** Два магазина — два кабинета, два входа, постоянное переключение.
**Feature.** Все магазины в одном боте.
**Mechanism.** Токены хранятся под именами; настройки, куки панели и данные
поставщиков разложены по аккаунтам; переключение одним нажатием.
**Benefit.** Не надо подключать заново.
**Deeper benefit.** Магазины не путаются между собой: у каждого свои правила и
свои остатки.
**Proof / Screenshot.** S-12 — с **вымышленными** названиями магазинов.
**CTA.** Низкой готовности.
**Оговорка — обязательная и в самой карточке.** Автоматика работает на
активном магазине, а не на всех сразу.

## B-5. Напоминания о зависших заказах (B6)

**Pain.** Заказ висит, покупатель молчит, продавец забыл.
**Feature.** Напоминание через заданное время (по умолчанию 24 часа).
**Mechanism.** Проход по заказам сверяет время без движения; отметка
сбрасывается при смене статуса.
**Benefit.** Ни один заказ не теряется из виду.
**Deeper benefit.** Меньше возвратов по причине «про меня забыли».
**Proof / Screenshot.** —
**CTA.** Низкой готовности.

## B-6. Премиум-поднятие по расписанию (G2)

**Pain.** Поднимать надо регулярно, а помнить об этом некому.
**Feature.** Расписание с денежным потолком.
**Mechanism.** Наступило время из списка — бот поднимает через панель; тратит
не больше заданного в сутки; при включении сегодняшние прошедшие слоты
помечаются выполненными, чтобы включение в 10:00 не подняло товар немедленно
за слот 09:00.
**Benefit.** Продвижение идёт по плану.
**Deeper benefit.** Расход предсказуем — потолок задаёт продавец.
**Proof / Screenshot.** S-19 (в составе экрана трат).
**CTA.** Низкой готовности.
**Оговорка.** Тратит деньги продавца; идёт через панель.

## B-7. Поставщик и прокси (F3)

**Pain.** Ключ поставщика перестал работать после обновления — и непонятно
почему.
**Feature.** Экран доступа к поставщику с проверкой прокси.
**Mechanism.** У поставщика белый список IP, а адрес сервера меняется при
каждом обновлении. Лечится прокси с постоянным адресом. Кнопка «🧪 Годится ли
он» **проверяет**: спрашивает адрес трижды и сверяет с прямым — ловит и
ротацию, и не применившийся прокси.
**Benefit.** Причина находится за минуту, а не за вечер.
**Deeper benefit.** Продавец перестаёт зависеть от поддержки в диагностике.
**Proof / Screenshot.** S-16 — адрес прокси скрыть.
**CTA.** Низкой готовности. Тема для образовательного поста, не для сайта.

## B-8. Создание товара под наличный номинал (F5)

**Pain.** Объявление на номинал, которого у поставщика нет, — это заказ,
который нечем выдать.
**Feature.** Кнопка «🏷 Создать товар» на карточке вида карты.
**Mechanism.** Читается наличие у поставщика → предлагаются номиналы, которые
**есть** → товар заводится по шаблону названия и описания.
**Benefit.** Ассортимент совпадает с тем, что можно выдать.
**Deeper benefit.** Меньше возвратов «товара нет в наличии».
**Proof / Screenshot.** в составе S-03.
**CTA.** Низкой готовности.

# Не продаётся вообще

| Функция | Причина |
|---|---|
| **A3 Копия товара по образцу** | закрыта флагом: только администратору |
| **A4 Залив** | тот же флаг |
| **M1 AutoStars (Telegram Stars)** | раздел скрыт целиком: покупка на Fragment не доведена |
| **K1 Админ-панель** | кабинет владельца |
| **L1 Скрытая диагностика** (`/version`, `*_debug` бота) | скрыта от продавца намеренно |
| **M7 `/pubg`** | честный ответ о несуществующем плагине |

Правило: пока флаг не снят, этих функций для маркетинга **не существует** — ни
как «скоро», ни как «в разработке», ни намёком на скриншоте.
