# 27. План измерений

**Главное ограничение раздела.** Целевых процентов здесь нет. Исторических
данных по сайту и каналу в аудите не существует, а придуманная норма хуже
отсутствующей: по ней принимают решения.

Вместо целей — **что измерять**, **с чем сравнивать** и **какое решение
принимать** по каждому показателю.

---

## Принцип

Сравниваем три вещи, и только их:

1. **Материал с материалом.** Пост A против поста B на одной аудитории.
2. **Период с периодом.** Эта неделя против прошлой.
3. **Шаг с шагом.** Сколько дошло с предыдущего этапа воронки.

Абсолютное число само по себе не значит ничего.

---

## Сайт

| Показатель | Что показывает | Решение по нему |
|---|---|---|
| **Hero → CTA** | сработал ли заголовок | низкий при высоком трафике → менять Hero (`07_HERO_CONCEPTS.md`) |
| **Глубина прокрутки** | где теряется внимание | обрыв на конкретном блоке → блок переписывается или переносится |
| **Досмотр демонстрации** | работает ли главный материал | бросают в первые секунды → менять раскадровку, не текст |
| **Взаимодействие с блоком возможностей** | какие функции интересны | подсказывает, что выносить выше |
| **Переходы в бота** | главный показатель сайта | всё остальное — промежуточное |
| **Подключение токена** | **настоящая конверсия** | переходы есть, подключений нет → ломается объяснение, где взять токен |
| **Доля дошедших до блока тарифов** | снят ли страх | мало → блоки контроля и границ не работают |

**Ключевое наблюдение.** Разрыв между «переходы в бота» и «подключение
токена» — самое дорогое место всей воронки: человек уже пришёл и ушёл ни с
чем. Чинится не сайтом, а объяснением токена **до** перехода.

## Telegram

| Показатель | Что показывает | Решение |
|---|---|---|
| **Охват поста** | попал ли в аудиторию | сравнивать посты между собой, не с нормой |
| **Пересылки** | **главный показатель TOFU** | пересылают полезное, не продающее. Образовательные посты без пересылок → темы не те |
| **Переходы в бота** | главный показатель MOFU и BOFU | считать отдельно по каждому посту |
| **Реакции** | вовлечённость | **не путать с переходами** |
| **Отписки после поста** | перегнули | всплеск после конверсионного → оффер прозвучал рано |
| **Рост подписчиков** | работает ли TOFU | останов → мало пересылаемого контента |

**Ключевое наблюдение.** Расхождение между **реакциями** и **переходами** —
главный сигнал канала. Пост может нравиться и не двигать: такой формат хорош
для охвата и бесполезен для воронки. Оба показателя нужны, но решения
принимаются по второму.

## Бот: активация

| Переход | Что показывает | Решение |
|---|---|---|
| запуск → подключение токена | самая дорогая потеря | низкий → чинить объяснение токена, не рекламу |
| токен → первое уведомление | время до aha moment | долго → сказать человеку, что уведомления уже работают |
| первое уведомление → первая автоматика | дошёл ли до пользы | низкий → предлагать **одно** действие, не список |
| **какая автоматика включена первой** | подсказка для onboarding | самая частая становится рекомендуемой |
| первая → вторая автоматика | углубление | предсказывает продление лучше, чем срок использования |
| вторая → подключение поставщика | самый ценный сегмент | низкий → объяснять `orders:write` и прокси заранее |

## Деньги

| Показатель | Что показывает |
|---|---|
| Доля взявших пробу от подключивших токен | работает ли ценность |
| Доля оплативших от взявших пробу | **главный показатель бизнеса** |
| Какой срок выбирают чаще | подсказка для тарифной сетки |
| Доля продливших | удержание |
| Сколько автоматик включено у оплативших против неоплативших | **связь пользы и оплаты** |

**Последняя строка важнее остальных.** Если у оплативших включено заметно
больше автоматик, значит путь к деньгам лежит через активацию, а не через
рекламу — и бюджет надо двигать туда.

---

## Что измерять в первую очередь

Полное измерение требует настройки. Если возможно только частичное, вот
порядок:

1. **Подключения токена** — без этого продукт не существует для человека.
2. **Переходы в бота по постам** — какие темы двигают.
3. **Первая включённая автоматика** — с чего начинать onboarding.
4. **Доля оплативших от взявших пробу** — работает ли продукт как бизнес.
5. Всё остальное.

---

## Как ставить цели, когда данные появятся

1. **Первый месяц — база.** Никаких целей. Только сбор.
2. **Второй месяц — гипотезы.** Берём худший показатель из воронки и ставим
   цель улучшить **его одного**.
3. **Дальше — по одному изменению за раз.** Две правки одновременно не дают
   понять, какая сработала.
4. **Сегменты считать отдельно.** Продавец карт и продавец ключей приходят по
   разным постам и активируются по-разному; общая цифра усредняет их в
   бессмыслицу.

---

## Чего не измерять

| Не измерять | Почему |
|---|---|
| «Узнаваемость бренда» | нечем мерить и не на что влиять на этом этапе |
| Лайки как показатель успеха | не коррелируют с переходами |
| Число публикаций | это усилие, а не результат |
| Подписчиков как главный KPI | канал из пяти тысяч без переходов бесполезен |
| Абсолютный охват без сравнения | зависит от алгоритма, а не от качества |

---

## Что ещё неизвестно и требует опроса

В аудите этих данных нет, и вывести их неоткуда. Каждый ответ меняет
приоритеты.

| Вопрос | Как узнать | Что изменит |
|---|---|---|
| Сколько магазинов у среднего продавца | опрос в канале | приоритет функции «несколько магазинов» |
| Какой объём делает ручную выдачу невыносимой | интервью с подписчиками | порог входа сегмента С-1 |
| Какая доля платит за продвижение | опрос | вес блока о позиции |
| Откуда приходят нынешние подписчики | вопрос при подключении | распределение бюджета |
| Что стало последней каплей перед оплатой | интервью с первыми клиентами | **главный оффер** |
| Чего не хватило неоплатившим | вопрос в конце пробы | что чинить в первую очередь |

**Последние два — самые ценные.** Они дают то, чего не даст никакая
аналитика: причину решения.
