# Выкат бота: чтобы не делать это руками

Цель — убрать из цепочки Termius. Пуш в рабочую ветку → сервер обновляется
сам, а если поднялась старая сборка, об этом говорится вслух, а не молча.

---

## Что откуда берётся

| | что делает |
|---|---|
| `scripts/deploy.sh` | всё обновление: забрать код, перезапустить, **сверить версию**. Запускается на сервере |
| `.github/workflows/deploy-bot.yml` | запускает его по SSH при пуше в рабочую ветку и по кнопке на github.com |
| `/health` в боте | отдаёт `{"status","version","storage","polling","last_update_ago"}` — по нему выкат понимает, доехал ли код и слышит ли бот Telegram |

**Главное свойство:** выкат заканчивается не словом «готово», а сверкой.
Скрипт спрашивает у поднявшегося бота его версию и сравнивает с той, что
только что выкатили. Не совпало — выкат объявляется неудачным, код
возвращается на прежний коммит, чтобы репозиторий и работающий бот снова
означали одно и то же. Это то же правило, из-за которого в `CLAUDE.md`
написано «после деплоя проверять `/version`»: «перезапустил» и «работает» —
разные утверждения.

---

## Настройка, один раз

**1. Ключ для выката.** На своей машине:

```bash
ssh-keygen -t ed25519 -f deploy_key -C "выкат yomarket" -N ""
```

Публичный (`deploy_key.pub`) — на сервер, в `~/.ssh/authorized_keys`.
Приватный (`deploy_key`) — в секреты GitHub, целиком, вместе со строками
`-----BEGIN…` и `-----END…`.

Отдельный ключ, а не ваш обычный: этот лежит у GitHub, и если он утечёт,
менять придётся только его.

**2. Секреты.** GitHub → репозиторий → **Settings** → *Secrets and variables*
→ **Actions** → *New repository secret*:

| имя | значение |
|---|---|
| `SSH_HOST` | адрес сервера |
| `SSH_USER` | пользователь |
| `SSH_KEY` | приватный ключ целиком |
| `DEPLOY_PATH` | каталог репозитория на сервере, например `/opt/yomarket` |

Необязательные:

| имя | зачем |
|---|---|
| `SSH_PORT` | если не 22 |
| `SSH_KNOWN_HOSTS` | вывод `ssh-keyscan -p ПОРТ адрес`. Без него ключ сервера принимается с первого предъявления — работает, но подмену сервера так не заметить |
| `HEALTH_URL` | чем сверять версию, например `http://127.0.0.1:8080/health`. Без него выкат прямо скажет, что версию **не сверял** |

**3. `PORT` на сервере.** Health-сервер поднимается только если задана
переменная `PORT`. В `docker-compose.yml` он уже задан (8080) и опубликован
**только на localhost**: наружу этот адрес отдавать незачем — он называет
версию бота и состояние приёма сообщений.

Выкат ищет порт в таком порядке: `HEALTH_URL` → переменная `PORT` → строка
`PORT=` в `.env` рядом с репозиторием. Не нашёл — так и скажет: «версия не
сверена». Угадывать порт он не станет: промах превратил бы удачный выкат в
«бот не ответил», то есть в ложную тревогу.

Проверить руками:

```bash
curl -s http://127.0.0.1:8080/health
```

Ответ вида `{"status":"ok","version":"…","polling":"ok","last_update_ago":12}`
означает, что бот жив **и слышит Telegram**. `"status":"deaf"` — процесс жив,
а обновления не приходят: обычно бот запущен где-то ещё с тем же токеном.

Пока секреты не заданы, workflow падает с красным крестом и списком того,
чего не хватает. Это правда: автовыкат не работает. Зелёная галочка на
невыполненном выкате была бы хуже.

## Как этим пользоваться

* **Само.** Пуш в `claude/where-we-left-off-mul8tu`, если в нём есть правки
  `bot/**` — сервер обновится.
* **С телефона, без терминала.** github.com → вкладка **Actions** → «Выкат
  бота на сервер» → **Run workflow**.
* **Руками на сервере.** `bash scripts/deploy.sh` — то же самое.
* **Через Claude Code на компьютере.** Из облачной сессии SSH недоступен
  (порт 22 закрыт, клиента нет), из локальной — доступен:
  `ssh сервер 'bash -s' < scripts/deploy.sh`.

## Что скрипт сделает и чего не сделает

**Определит сам**, чем запущен бот: `docker compose`, служба systemd (ищется
по тому, что она запускает, а не по имени) или просто `python main.py`. Что
нашёл — напечатает. Не нашёл — **откажется**, а не сделает вид: «не понял,
чем запущен бот» и список того, что проверял. Подсказать можно так:

```bash
SERVICE_NAME=yomarket.service bash scripts/deploy.sh
DEPLOY_RESTART_CMD='docker compose up -d --build' bash scripts/deploy.sh
```

**Не выбросит вашу работу на сервере.** Слияние идёт `--ff-only`: если на
сервере есть свои коммиты или незакоммиченные правки, выкат остановится и
скажет об этом. `git reset --hard` в выкате однажды стирает то, что правили
прямо на боевом, и найти это потом негде.

**Не соврёт про сверку.** Нет `HEALTH_URL` или `curl` — так и напишет:
«обновление выполнено, версия не сверена», и отправит смотреть `/version`
руками.

**Откатит при несовпадении версий** — вернёт код на прежний коммит. Отключить
для разбора: `NO_ROLLBACK=1`.

**Не откатит, если бот вообще не ответил.** Старая сборка к этому моменту
уже заменена, и откат вслепую сделал бы хуже; скрипт покажет, какой командой
смотреть логи.

## Осторожно: два бота с одним токеном

Telegram отдаёт обновления только одному потребителю. Если бот останется
запущенным и на Railway, и на своём сервере, они будут отбирать updates друг
у друга: часть сообщений теряется, в логах `Conflict: terminated by other
getUpdates request`. Симптом со стороны продавца — «бот отвечает через раз».

Поэтому: **где-то один должен быть выключен.** И проверять это стоит первым
делом, если после переезда бот ведёт себя странно.

## Проверено

`bot/tests/test_deploy.py` — 26 тестов, которые запускают `deploy.sh`
по-настоящему: временный репозиторий, подставной health-эндпоинт. Проверяется
не текст скрипта, а следствия: совпавшая версия → успех; старая версия →
неудача и откат; молчащий health → «не подтверждено»; правки на сервере
переживают выкат; неизвестный способ запуска → отказ, а не тишина.

Два настоящих дефекта эти тесты уже поймали. При `pipefail` неудачный
`systemctl` (а он падает везде, где systemd не запущен) ронял скрипт молча —
ни строчки в выводе, только код возврата 1. И сверка версии не работала ни у
кого: порт бота лежит в `.env`, а в окружении того, кто запускает выкат, его
нет — скрипт каждый раз честно писал «версия не сверена», то есть проверка
была написана и вхолостую.

## Переезд на свой сервер с нуля

`scripts/deploy.sh` обновляет уже настроенный сервер. Первичная настройка —
`scripts/setup-server.sh`: ставит зависимости, клонирует код, спрашивает
секреты, заводит службу systemd и проверяет, что бот поднялся И слышит
Telegram.

```bash
# на сервере, под root
export REPO_URL=https://github.com/ВАШ_АККАУНТ/Yomarket.git
export DEPLOY_PATH=/opt/yomarket
bash setup-server.sh
```

Скрипт спросит четыре вещи:

| Переменная | Обязательна | Что будет без неё |
|---|---|---|
| `BOT_TOKEN` | **да** | бот не запустится вовсе |
| `SECRET_KEY` | **да** | seed-фразы кошельков лягут в базу **открытым текстом** |
| `DATABASE_URL` | нет | данные в JSON-файлах; на своём сервере они переживают перезапуск |
| `PORT` | нет | health-сервер не поднимется, и выкат не сможет сверить версию |

**`SECRET_KEY` при переезде — тот же самый, что был на старом сервере.**
Новый ключ означает, что зашифрованные seed-фразы не расшифруются, и
выяснится это на первой же выдаче звёзд. Скрипт об этом предупреждает и
существующий `.env` не перезаписывает никогда.

### Порядок переезда, чтобы ничего не потерять

1. **Снять данные со старого места.** Если там PostgreSQL — перенести базу.
   Если JSON-файлы — скопировать каталог данных (`/version` в боте
   показывает, что именно используется).
2. Настроить новый сервер скриптом.
3. **Остановить бота на старом месте.** Два бота с одним токеном
   конфликтуют: Telegram отдаёт обновления одному, и часть сообщений
   теряется. Со стороны продавца это «отвечает через раз».
4. Проверить `/version` в боте — версия должна совпасть с той, что в коде.
5. Проверить `/health` — `status: ok`, а не `deaf`.

### Дальнейшие обновления

```bash
sudo -u ПОЛЬЗОВАТЕЛЬ DEPLOY_PATH=/opt/yomarket bash /opt/yomarket/scripts/deploy.sh
```

Либо через GitHub Actions — секреты `SSH_HOST`, `SSH_USER`, `SSH_KEY`,
`DEPLOY_PATH` в настройках репозитория. **`SSH_KEY` — приватный ключ, а не
пароль**: пароль в секретах GitHub не поддерживается, да и на публичном IP
с паролем сервер живёт до первого сканера.

## С телефона через Termius

Порядок для чистого сервера. Всё, что надо набирать руками, сведено к
минимуму: на телефоне опечатка — главный враг.

### 1. Добавить сервер

**Hosts → +** → `Address` — адрес сервера, `Username` — логин, `Password` —
пароль. Подключиться, согласиться с отпечатком ключа.

### 2. Перестать входить по паролю

Публичный адрес с паролем сканеры находят за часы, а на сервере будут лежать
seed-фразы чужих кошельков. Ключ нужен и для автовыката из GitHub Actions —
пароль тот не принимает вовсе.

**Keychain → + → Generate key** (ED25519, без пароля), затем в настройках
хоста **Use key** вместо пароля. Termius сам положит публичный ключ на
сервер при первом входе по паролю (кнопка «Copy key to server»), либо
вручную:

```bash
mkdir -p ~/.ssh && chmod 700 ~/.ssh
echo 'СЮДА_ПУБЛИЧНЫЙ_КЛЮЧ' >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys
```

Убедившись, что вход по ключу работает, закрыть парольный:

```bash
sudo sed -i 's/^#\?PasswordAuthentication.*/PasswordAuthentication no/' /etc/ssh/sshd_config
sudo systemctl restart ssh
```

### 3. Положить код на сервер

**Если репозиторий публичный** — одной командой:

```bash
curl -fsSLO https://raw.githubusercontent.com/ВАШ_АККАУНТ/Yomarket/claude/where-we-left-off-mul8tu/scripts/setup-server.sh
sudo REPO_URL=https://github.com/ВАШ_АККАУНТ/Yomarket.git DEPLOY_PATH=/opt/yomarket bash setup-server.sh
```

**Если приватный** — ключом развёртывания, без токенов в файлах:

```bash
ssh-keygen -t ed25519 -f ~/.ssh/github -N '' -C yomarket-server
cat ~/.ssh/github.pub
```

Показанную строку скопировать (в Termius — долгое нажатие → Copy) и вставить
на github.com: **репозиторий → Settings → Deploy keys → Add**, галку «Allow
write access» НЕ ставить. Затем:

```bash
printf 'Host github.com\n  IdentityFile ~/.ssh/github\n  IdentitiesOnly yes\n' >> ~/.ssh/config
sudo mkdir -p /opt/yomarket && sudo chown $USER:$USER /opt/yomarket
git clone -b claude/where-we-left-off-mul8tu git@github.com:ВАШ_АККАУНТ/Yomarket.git /opt/yomarket
sudo DEPLOY_PATH=/opt/yomarket bash /opt/yomarket/scripts/setup-server.sh
```

Скрипт видит, что репозиторий уже на месте, и клонировать не пытается.

### 4. Ответить на четыре вопроса

Скрипт спросит `BOT_TOKEN`, `SECRET_KEY`, `DATABASE_URL` и `PORT` — что это
и что будет без них, написано выше в разделе про переезд. **`SECRET_KEY`
берётся со старого сервера**, а не придумывается новый.

Закончит он не словом «готово», а сверкой: та ли версия поднялась и слышит
ли бот Telegram.

### 5. Сохранить команды в Snippets

Это то, ради чего Termius и стоит на телефоне: **Snippets → +**, команду
сохранить, дальше запускать одним нажатием на любом хосте.

| Название | Команда |
|---|---|
| Обновить бота | `sudo -u $USER DEPLOY_PATH=/opt/yomarket bash /opt/yomarket/scripts/deploy.sh` |
| Логи | `journalctl -u yomarket -n 50 --no-pager` |
| Логи вживую | `journalctl -u yomarket -f` |
| Состояние | `systemctl status yomarket --no-pager` |
| Перезапуск | `sudo systemctl restart yomarket` |
| Версия и слух | `curl -s localhost:8080/health` |

Последняя — самая полезная: `"status":"ok"` означает, что бот слышит
Telegram, `"deaf"` — что не слышит, и тогда смотреть логи.
