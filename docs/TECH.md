# Юмаркет Менеджер — техническое описание

Документ для разработчика (или для другой языковой модели), которому нужно
понять устройство бота целиком, не читая 50 тысяч строк. Составлен по коду,
а не по памяти: все числа, имена функций и размеры модулей взяты из дерева
на момент версии `2026-09-09-quiet-alarm`.

Что это: Telegram-бот автоматизации продаж для продавцов маркетплейса
Юмаркет (цифровые товары — игровая валюта, аккаунты, ключи, подарочные
карты, Telegram Stars). Продаётся по подписке; один процесс обслуживает
всех продавцов сразу, у каждого свой токен магазина и свой набор фоновых
задач.

---

## 1. Стек и точка входа

| Что | Чем |
|---|---|
| Язык | Python 3.11+, `from __future__ import annotations` везде |
| Telegram | aiogram 3.30, long polling (не вебхук) |
| HTTP наружу | `aiohttp` (асинхронно), `requests` (панель Nova — синхронно, в потоке) |
| Хранилище | PostgreSQL через `psycopg2` (пул 1–8) при `DATABASE_URL`, иначе JSON-файлы |
| Шифрование | `cryptography.Fernet`, ключ из `SECRET_KEY`/`FRAGMENT_KEY` |
| Планировщик | собственные `asyncio`-циклы, без Celery/APScheduler |
| Тесты | `unittest`, 3199 тестов в 107 файлах, без внешней сети |
| Деплой | Railway (Dockerfile) либо свой сервер по SSH (`scripts/deploy.sh`) |

Переменные окружения (`bot/config.py` читает только первую, остальные —
по месту):

| Переменная | Обязательна | Зачем |
|---|---|---|
| `BOT_TOKEN` | да | токен Telegram; читается ровно в одном месте |
| `DATABASE_URL` | нет | PostgreSQL; без неё файлы, а на Railway они стираются при редеплое |
| `SECRET_KEY` (или `FRAGMENT_KEY`) | на Railway — да | ключ шифрования seed-фразы TON |
| `DATA_DIR` | нет | каталог файлов хранилища |
| `PORT` | нет | поднимает health-сервер; без неё выкат не может сверить версию |
| `TELEGRAPH_TOKEN` | нет | только для `scripts/publish_legal.py` |

Ничего из этого в репозиторий не попадает: `.env` в `.gitignore`, токены,
куки и seed-фраза живут в окружении и в хранилище.

## 3. Запуск: `bot/main.py`

### 3.1. Порядок middleware — он значимый

```python
dp.message.outer_middleware(NoticeUpdates())          # 1
dp.callback_query.outer_middleware(NoticeUpdates())
dp.message.outer_middleware(HideSystemCommands())     # 2
dp.message.outer_middleware(CommandsEscapeForms())    # 3
dp.message.middleware(AccessMiddleware())             # 4
dp.callback_query.middleware(AccessMiddleware())
dp.message.middleware(YooMarketMiddleware())          # 5
dp.callback_query.middleware(YooMarketMiddleware())
```

1. **`NoticeUpdates`** — отметка «обновление пришло». Она же отменяет
   тревогу о немоте (см. §10). Стоит первой намеренно: обновление
   доказывает, что приём работает, даже если дальше его съест заслон.
2. **`HideSystemCommands`** — служебная команда от не-владельца обрабатывается
   так же, как несуществующая: молча. Ответ «эта команда не для тебя»
   рассказывал бы о существовании скрытой части.
3. **`CommandsEscapeForms`** — в боте 93 экрана, ждущих ввода; любой из них
   съел бы пришедшую команду. Внешний middleware закрывает незаконченную
   форму. Сверяется и с подписями кнопок постоянной клавиатуры — они
   приходят обычным текстом. Пустая форма закрывается молча, ожидание
   токена — всегда молча (его взводит сам бот).
4. **`AccessMiddleware`** — блокировки и подписка. Список свободного входа
   узкий и закрытый: `FREE_COMMANDS = ("/start", "/policy", "/forget_me")`,
   `FREE_CALLBACKS` (тарифы, пробы, покупка, поддержка, документы),
   `FREE_PREFIXES = ("sub:buy:", "sub:m:", "pay:paid:")`. Заперев покупку
   подпиской, мы заперли бы единственный способ подписку купить.
5. **`YooMarketMiddleware`** — кладёт в `data["api"]` готовый
   `YooMarketAPI(token)` продавца; хендлеры принимают его параметром.

### 3.2. Порядок роутеров — тоже значимый

`admin → start → balance → ads → create_ad → panel_items → packs → accounts →
prices → orders → chats → settings → notifications → autopilot → auto_settings →
selenium_settings → responders → nsgifts → approute → plugins → stats → panel →
policy → subscribe → commands → fallback`

Две команды с одним именем — не ошибка, а тишина: побеждает роутер,
подключённый раньше. Тест в `test_chat_chain.py` разбирает `handlers/*.py`
в AST и падает на дубле. `fallback` последний — он ловит остальное.

### 3.3. Что делается при старте

```
clear_webhook(bot)     # вебхук на токене глушит polling полностью
publish_commands(bot)  # клиентский список — в область по умолчанию,
                       # владельцу — полный, в его чат
TaskManager(bot).start_all()
_start_health_server() # только если задан PORT
dp.start_polling(bot)
```

`clear_webhook` не выбрасывает накопленные обновления — это заказы.

## 5. Фоновая работа: `bot/tasks/manager.py`

`TaskManager` держит на **каждого продавца три задачи** и **одну общую на
весь бот**:

| Задача | Период | Что делает |
|---|---|---|
| `_user_loop` → `_tick` | 60 с | заказы, напоминания, расписание поднятий, залив |
| `_chat_loop` → `_chat_tick` | 10 с (подбирается) | только чаты и автоответы |
| `_auto_loop` → `_tick_auto` | 30 мин | автовосстановление, отзывы, позиция, сессия панели, дневной отчёт |
| `_purge_loop` (общая) | 6 ч | удаление данных через 3 дня после конца подписки |

**Замок на продавца** (`self._locks[uid]`, `asyncio.Lock`): проход по
заказам, проход авто-функций и проход чатов все читают-правят-сохраняют
весь словарь настроек целиком. Без очереди тот, кто сохранит последним,
молча затрёт правки другого — например, очередь звёзд против
`bump_schedule.last_runs`.

### 5.1. Темп опроса чатов

Сколько запросов в минуту разрешает Юмаркет — нигде не написано, поэтому
темп не угадывается, а нащупывается:

```python
_CHAT_FAST     = 10.0    # пол
_CHAT_SLOW     = 120.0   # потолок отступления
_CHAT_BACKOFF  = 2.0     # отступ на «сбавьте темп»
_CHAT_RECOVER  = 0.8     # возврат после чистого прохода
_CHAT_PARALLEL = 6       # чатов читается сразу
_CHAT_POLL_LIMIT = 25    # сколько чатов под наблюдением
_CHAT_HOT_AGE  = 2*3600  # «горячий» заказ
_CHAT_FULL_EVERY = 60.0  # полный обход
```

Быстрый проход раз в 10 секунд читает только **горячие** чаты (покупатель
ждёт ответа либо заказ моложе двух часов). Полный обход всех 25 — раз в
минуту. 25 чатов каждые 10 секунд дали бы полтораста запросов в минуту,
маркетплейс ответил бы «сбавьте темп», и вышло бы медленнее, чем было.

Сеть — параллельно (`_fetch_chats`, семафор на 6), **разбор — по одному**:
он правит общие настройки продавца, и две правки одного словаря затрут
друг друга. Ошибка не бросается, а кладётся в результат: один упавший чат
не уносит остальные 24.

### 5.2. Ожидание кода от поставщика

`_GIFT_POLL_CEILING = 120.0` и `_ROBUX_POLL_CEILING = 120.0`, шаги
`(12, 12, 15, 20, 30, 30, 30, 45, 60, 60)`. Ожидание занимает поток, а
замок общий с опросом чатов; недоведённую выдачу подбирает `_gift_resume`.

## 6. Хранилище: `bot/storage.py`

### 6.1. Два бэкенда, один интерфейс

`DATABASE_URL` → PostgreSQL (`kv_store`: ключ → JSON-текст). Без неё —
JSON-файлы в `DATA_DIR`. Один и тот же набор «блобов»:

```
tokens.json  settings.json  panel_creds.json  fragment_creds.json
ns_creds.json  approute_creds.json  admin.json
```

**Запись в файлы атомарна**: `.tmp` + `os.replace` + `fsync`. Прежний
`open(path, "w")` обнулял файл до записи, и процесс, убитый посередине,
оставлял обрезанный JSON — то есть не «часть настроек», а ноль: разбор
падал на всём файле, продавец терял токен, правила и цены разом.

`ephemeral_disk()` отвечает, стирается ли хранилище при редеплое (Railway
без `DATABASE_URL`); `/version` это показывает.

### 6.2. Схема настроек продавца

`get_settings(uid)` возвращает словарь, дополненный `_DEFAULT_SETTINGS`.
Ключи верхнего уровня:

| Ключ | Что внутри |
|---|---|
| `shop_name` | название магазина |
| `auto_reply`, `auto_events`, `auto_rules` | простые автоответы (наследие) |
| `autoreplies` | нынешние правила: `{enabled, rules[], log[], state{}}` |
| `auto_restore` | автовозврат распроданного: интервал, `instant`, `require_stock`, `failures{}` |
| `auto_bump`, `bump_schedule` | поднятие по интервалу и по расписанию, с денежным потолком |
| `promo_position` | слежение за позицией: `watches[]`, `cooldown_hours`, `daily_limit`, `daily_budget` |
| `auto_withdraw` | реквизиты вывода через панель (автовывода нет) |
| `known_orders`, `known_order_ids`, `known_order_details`, `known_messages` | что бот уже видел |
| `watched_chats` | чаты без заказа (списка чатов в API нет) |
| `reminders`, `reminded_orders` | напоминания по заказам |
| `auto_accept`, `auto_confirm`, `auto_refund` | автоматика по статусам; возврат по умолчанию выключен |
| `notify_orders`, `notify_messages`, `balance_notify`, `complaint_notify` | уведомления |
| `daily_report`, `quick_replies`, `ad_packs`, `reviews_monitor` | прочее |
| `plugins` | `auto_stars`, `auto_roblox`, `auto_gifts` |
| `pour` | **залив** (см. ниже) |
| `copy_marks`, `copy_stock` | память копии: раздел/подраздел/тип за образцом, заготовка остатков |

Схема залива (`get_pour` / `save_pour`):

```python
{
  "enabled": bool,
  "every": int,        # шаг в минутах, минимум 1
  "items": [ad_id],    # какие товары заливать
  "made": [item_id],   # что бот создал сам; хвост в _POUR_MADE_MAX = 3000
  "last_run": float,
  "log": [str],        # последние 30 записей
  "from_hour": int, "to_hour": int,   # окно по часам продавца, работает через полночь
  "cap": int,          # потолок копий на товар в сутки, 0 — без потолка
  "keep": int,         # сколько копий держать на витрине
  "gap": int,          # пауза между товарами, секунды
  "publish": bool,     # публиковать ли сразу
  "day": str, "today": {ad_id: int},  # счётчик суток продавца
  "stock": {ad_id: [str]},            # СВОИ остатки товара
  "next_i": int,       # круговая очередь: с кого начинать следующий проход
}
```

### 6.3. Шифрование

Seed-фраза TON шифруется `Fernet`, ключ — из `SECRET_KEY` или
`FRAGMENT_KEY`, приводится к длине **хешем, а не обрезанием**. Префикс
шифротекста `enc:v1:`.

Подстраховки «ключа нет — выведем свой» **нет намеренно**: ключ, собранный
из того, что лежит рядом с шифротекстом, шифрованием не является. Нет
ключа — храним как раньше, и `/version` говорит об этом прямо. Секретные
поля поставщиков (`api_secret`, `password`, `api_key`, `proxy`) шифруются
тем же путём.

### 6.4. Подписки и деньги

`grant_subscription(uid, days, by)` **прибавляет** к остатку, а не
заменяет: три дня без условий и семь за подписку на канал складываются в
десять. Оплаченную подписку от пробной отличает поле `by` (у пробной ноль).
`LIFETIME_DAYS = 36500` — «навсегда» это очень большой срок, а не особый
случай; исключение живёт только в показе (`term_label`, `is_lifetime`).

Тарифов шесть: 2 недели, 1, 3, 6, 12 месяцев, «Навсегда». Цена за срок,
которого нет в `PRICE_TIERS`, не показывается никому. Тест в
`test_pricing.py` сверяет, что `docs/legal/offer.md` перечисляет то же,
что продаёт бот.

## 7. Внешние интерфейсы

### 7.1. Integration API — `https://api.yoo.market/integration/v1`

Авторизация: `Authorization: Bearer <токен магазина>`. Клиент —
`bot/api/yoomarket.py`, класс `YooMarketAPI`.

Что стоило часов и проверено на живом магазине:

* **Цена приходит объектом**, не числом:
  `{"amount": 129, "base_amount": 129, "currency": "RUB"}`. Читать только
  через `orderfields.ad_price` / `order_price`; как скаляр объект
  превращается в ноль.
* **Курсор лежит в `links.next_cursor`**, а не в `meta.next_cursor`.
  Разбирает его **одно** место — `next_cursor()` в клиенте. Семь экранов
  читали его каждый у себя, и у всех семи кнопки «Следующая →» не было
  вовсе. `meta.has_more == false` — стоп даже при непустом курсоре.
  `links.next` у Laravel бывает полным адресом — отправленный курсором, он
  вернул бы ту же страницу.
* **Первая страница — это не «все».** `get_all_ads()` листает (до 25
  страниц); `get_ads()` оставлен экранам со своей листалкой.
* **Справочник разделов целиком не вычитывается** — их больше четырёх
  тысяч. Имена спрашиваются поимённо: `resolve_category(cid)`, с памятью
  на продавца. Цепочка «лист → игра → раздел» собирается **подъёмом по
  `parent_id`** (`_path_upwards`), обход сверху — запасной путь.
* **Сообщения лежат под чатом**: `GET /chats/{chat_id}/messages`. Номер
  чата ≠ номер заказа, он в `known_order_details[oid]["chat_id"]`.
* **Переписка отдаётся от новых к старым**; порядок нормализован в
  `_msg_rows`, все читатели идут через него.
* **В закрытый заказ писать нельзя**: `no_active_orders_in_chat`.
* **Публикация — через API** (`POST /ads/{id}/publish`), а не через панель:
  панель на своё же «Опубликовать» отвечает 200 и текстом «нет прав».
  Статус после публикации перечитывается.
* **Статус `unpublish` через API не публикуется** — `_MANUAL_ONLY` в
  клиенте. Маркетплейс принимает запрос (HTTP 200), статус не меняется.
* **`accepted` ≠ «положил».** `POST /ads/{id}/items` отвечает
  `{"status":"ok","accepted":1}`, а список сразу после этого прежний.
  Поэтому `confirm_items(api, ad_id, want)` перечитывает по
  `_CONFIRM_WAITS = (0.0, 3.0, 7.0)` и останавливается, как только позиций
  стало достаточно. `items_accepted(answer)` различает «не сказал» (−1) и
  «принял ноль» (0) — это разные ответы.
* **Список позиций читает одно место** — `ad_items_free` в
  `orderfields.py`. Читателей было четверо, и разбирали они `/ads/{id}/items`
  каждый по-своему. Позиция **без статуса считается свободной**: у только
  что положенной его может не быть.
* **Чего в API нет вовсе:** поднятия объявлений, вывода средств, отзывов,
  изменения цены. Всё это только через панель. `test_dead_buttons.py`
  следит, чтобы удалённые методы не вернулись.

### 7.2. Панель Nova — `https://panel.yoomarket.net`

Сессионные куки, вход по email + одноразовый код (`/token`, `/code`).
Обновление: `POST /nova-api/{resource}/{id}/update-fields` с `_method=PUT`.
Модуль `bot/automation/panel.py` (5293 строки), вызовы **синхронные**
(`requests`) и уходят в поток.

* **HTTP 200 — не доказательство.** `panel_update_item_sync` перечитывает
  поле после записи и сравнивает.
* **У товара (`items`) нет поля цены.** Менять цену из бота невозможно в
  принципе; функция снята намеренно.
* **Источников по товару три, и Nova разрешает их независимо:**
  форма правки `/nova-api/items/{id}/update-fields`, карточка
  `/nova-api/items/{id}`, строка списка `/nova-api/items?search=…`.
  403 на любой из них у своего товара — обычное дело и **не** «товар не
  прочитать». Закрытая форма правки копию не отменяет.
* **Цену и остаток с карточки не берём никогда** — они уже оформлены
  («1 490 ₽»), числа из такой строки не достать (`_is_formatted_number_attr`).
* **Раздела у товара в панели нет нигде** — ни в форме правки, ни на
  карточке, ни в строке списка. Панель задаёт его один раз при создании и
  больше не показывает.
* **Обязательность полей зависит от раздела, и форма о ней молчит.**
  Форма создания отдаёт `Обязательные: []`, а после выбора категории
  приходит 422: «filter__8: Поле Регион обязательно». `validation_fields`
  + `_ask_for_refused_fields` спрашивают и досылают.
* **`filter__1`…`filter__11` — атрибуты раздела** (у гифт-карт `filter__8`
  = «Регион»).
* **Ссылки в описании запрещены**, кроме белого списка (`PANEL_LINK_ALLOWED`:
  Warface, YouTube, Rutube, VKVideo, Google/Яндекс/Майл Диск). Проверка
  заранее — `link_trouble`, объяснение отказа — `explain_validation`.
* **Список вариантов панель отдаёт обрезанным.** Без слова для поиска
  `associatable` присылает первые несколько сотен по алфавиту. «Нет в
  списке» ≠ «нет вовсе»: бот спрашивает панель по надписи образца сам.
  Живой ответ отдал **825** разделов, а сверка шла по первым пятистам.

### 7.3. Поставщики

**AppRoute** — `https://approute.io/api/v1`, заголовок `X-API-Key`.
Справочник: `docs/approute_api_reference.md`.

* HTTP 200 всегда; всё существенное в конверте
  `{status, statusCode, statusMessage, traceId, data, errors}`.
* Получилось ли — решает **`statusCode`**, а не HTTP. Успех: `0` OK,
  `1` ACCEPTED, `2` IDEMPOTENCY_REPLAY. Отказы: 3 VALIDATION, 4
  UNAUTHORIZED, 5 FORBIDDEN, 6 NOT_FOUND, 8 LIMIT_REACHED, 9 OUT_OF_STOCK,
  10 INSUFFICIENT_FUNDS, 11 UPSTREAM_ERROR.
* `status`: `SUCCESS`, `IN_PROGRESS` (HTTP 202, кода ещё нет — ждать
  опросом), `PARTIALLY_COMPLETED` (терминальный), `CANCELLED`.
* На проводе **camelCase** (`itemId`, `referenceId`, `clientTime`).
* Тело покупки: `{"ordersType":"shop","orders":[{"denominationId":"…",
  "quantity":1}]}`, позиция ровно одна, `referenceId` наверху.
* Коды в `GET /orders` замазаны; полные — только по
  `?referenceId=…&unhide=true`, и у запроса есть побочное действие.
* Право `orders:write` — это не «запись», а выдача кодов: без него ключ
  покупает, но кода не отдаёт.
* **Белый список IP.** Бот живёт на Railway, где адрес меняется при каждом
  выкате; лечится прокси с постоянным адресом. Через прокси обязаны идти и
  рабочие вызовы, и диагностика — одна точка `_session`.
* Лимиты открыты: `GET /api/v1/rate-limits`. `GET /services` и
  `GET /orders` — по 2 в минуту, `POST /orders` и
  `GET /services/{id}/items/{id}` — 120.

**ns.gifts** — `bot/automation/nsgifts.py`, справочник
`docs/ns_api_reference.md`.

**Fragment (звёзды)** — `bot/automation/fragment.py`. Плагин **скрыт**
(`features.STARS_HIDDEN = True`): покупка доведена не до конца. Прячется
целиком — кнопка, команды, диагностика, строка в приветствии, прокси и обе
точки входа фоновой выдачи. Ключевые факты: всё уходит в строку запроса,
единственный заголовок `User-Agent`, хеш всегда читается со страницы
`/stars/buy`, признак входа — только `/logout` или `my assets`.

### 7.4. Публичная витрина

`bot/automation/market.py` и `position.py` — позиции товара в списке
предложений нет в API продавца, она есть только на витрине, оттуда и

## 8. Копия товара и залив

Самая большая подсистема после панели. Живёт в `handlers/create_ad.py`.

### 8.1. Копия по образцу

Создаёт копию **тем же вызовом**, что и мастер
(`panel_create_product_sync` через `_panel_create_and_report`), — путь,
которым заведены все товары продавца.

Конвейер:

```
copy_item / pour_once
  └─ _run_copy(msg, state, uid, ad_id, cid, api)
       ├─ _copy_source_values(uid, ad_id, api)     ← панель + маркетплейс
       │    ├─ panel_item_values_sync              values + extra + labels
       │    ├─ _ad_card / _price_from_api          название, описание, цена
       │    └─ _section_words / category_path      слова для поиска раздела
       ├─ _creation_form(uid)                      поля формы СОЗДАНИЯ
       ├─ _select_queue(fields) → _ask_next_select очередь списков
       ├─ _panel_create_and_report(...)            multipart в панель
       ├─ _fill_stock(api, item_id, want, ...)     остатки после создания
       └─ publish_ad / panel_publish_item_sync     публикация
```

Правила, каждое написано по живому отказу:

* **Раздел уходит номером, а не надписью** — у полей BelongsTo выбранное
  лежит в `belongsToId` (`_field_submit_value`).
* **«subcategory» содержит «categ»** — имя сверяется точно, иначе номер
  подраздела уезжает в `values["category"]` и товар ложится не туда.
* **Переносится всё, что у товара есть**, но отправляется только то, что
  знает форма создания: `public` и `moderation_status` у товара есть, при
  создании их нет.
* **Каждое поле берётся оттуда, где оно есть**: раздел и `filter__N` — у
  панели, цена и остаток — у маркетплейса. Не прочитавшаяся цена — отказ,
  а не ноль.
* **Картинка скачивается сессией панели и кладётся файлом**; адрес бывает
  относительным. Файл не удаляется сразу — после ответа на вопрос товар
  уходит заново.
* **Запрещённое слово бот убирает сам и отправляет заново**, ровно один
  заход (`cleaned`), вместе с окончаниями, и ищет его **только в жалобах
  панели** — в отчёт попадает и наш собственный дамп «Отправлено: {…}».
* **Готовый номер сверяется со списком формы**, а не отправляется на веру.
  Порядок: номер образца → надпись образца → слово. Не сошлось — вопрос.
* **Раздел ищется в тексте товара**, а не своими словами в списке панели
  (`_match_by_text`): по целым словам, длинное побеждает, название важнее
  описания, два равных — не выбор.
* **Память двухслойная**: за товаром (`copy_marks`) и за разделом
  маркетплейса (`cat:{id}`). Запоминается **только после того, как панель
  товар приняла**, и читается **до** закрытия формы.
* **Приоритет источников типа выдачи** — одна строка:
  `chosen = {**marks, **from_market, **extra}` (панель важнее маркетплейса,
  маркетплейс важнее памяти). На каждую пару стоит свой тест.

### 8.2. Остатки

`_fill_stock(...) -> (отчёт, положено, это_заготовка)` — третье значение
управляет кнопкой «📦 Прислать остатки». **Никогда не разбирайте
собственный текст отчёта.**

Вид товара решает, что бот может сделать сам:

| Вид | Что делает бот |
|---|---|
| `unlimited` | ничего: остатка нет вовсе |
| `auto-value` | ставит число целиком, вместе с `min`, `max`, `step`, `label_id` |
| `auto-delivery` | остаток — сам товар (коды, аккаунты): просит прислать |
| остальное | пробует пополнить и печатает ответ маркетплейса |

Источник строк — `_default_stock(uid, source_id)`: сначала список **этого**
товара (`pour.stock[ad_id]`), потом общая заготовка (`copy_stock`). Одна
заготовка на разные игры кладёт покупателю ключ от чужой.

Первый присланный список сам становится заготовкой (`_remember_stock` в `handlers/panel_items.py`) —
и об этом говорится вслух; записывается только когда своей ещё нет.
Не принятый маркетплейсом список заготовкой не запоминается.

### 8.3. Залив (`pour`)

Залив — та же копия, по расписанию. Идёт **тем же кодом**: `_run_copy`
вынесен из обработчика ради этого.

```
_tick (раз в минуту)
  └─ _maybe_pour(uid, settings)
       ├─ окно часов, шаг, потолок суток, круговая очередь
       ├─ pour_once(uid, ad_id, cid, api, publish)   ≤ _POUR_PER_PASS = 5
       │    └─ _run_copy с _Quiet + _MemState({"silent": True})
       ├─ conf["made"].append(item_id)
       └─ _pour_delete(uid, item_id)  — только свои вчерашние копии
```

* **Спросить некому**, поэтому вопрос становится пропуском с причиной:
  признак `silent` в состоянии, `_ask_next_select` пишет
  `silent_stop=<поле>` и возвращается. Не разбор собственного текста.
* **Состояние своё** — `_MemState`, `_Quiet`: настоящий FSM привязан к
  чату, а заливу нужно то же хранилище на несколько секунд и без чата.
* **Успешное создание не закрывает форму при заливе**: номер созданного
  товара лежит именно в состоянии, и завтра по нему этот товар удаляют.
* **Удаляются только свои копии** — те, чьи номера записаны в `made`.
  Не удалившаяся копия остаётся в списке: забыть номер значит потерять
  единственный след.
* **«Вчерашние» считаются по дню продавца**, а не «прошло 24 часа».
* **Не больше 5 товаров за проход**, очередь круговая (`next_i`): копия —
  это чтение панели, создание, остатки с ожиданием и публикация, секунд
  пятнадцать на товар, а в том же проходе идут заказы и напоминания.
* **Факты о результате возвращаются наружу**: `silent_stock_ok`,
  `silent_stock`, `silent_pub_ok` кладутся в состояние, `pour_once` их
  возвращает, журнал печатает «✅» или «⚠️ без остатка · причина».
* **Одинаковые товары сворачиваются** (`_group_same`, ключ `_same_key` —
  название без регистра и лишних пробелов) с числом копий в скобках.
  Образцом группы берётся тот, которого бот **не** создавал, среди своих —
  самый старый номер.
* **Выбор товаров идёт страницами** (`_POUR_PER_PAGE = 12`), отметка
  возвращает на ту же страницу.

Копия доступна только админам (`features.ad_templates_shown`) и требует
токена: и список, и создание идут по API.

## 9. Интерфейс: `bot/ui.py`, клавиатуры, ограничения Telegram

* `ui.screen/card/head` — каркас экранов, `ui.esc` — экранирование HTML
  (одиночный `<` из письма покупателя роняет всю отправку).
* `ui.lay(builder)` — раскладка по **ширине надписей**, не по `len`:
  «↩️ Возвраты» — это 11 кодовых точек при 9 нарисованных знаках, ширину
  считает `ui.width`. Экраны подтверждения раскладке не подлежат
  (`adjust(1)`), безвозвратная кнопка выносится строкой через
  `ui.lay(b, solo={"bl:clear"})` — по `callback_data`, не по надписи.
* `adjust` переставляет **всю** клавиатуру, а не новые ряды; два `adjust`
  подряд — это один.
* `ui.copyable` — моноширинный блок с копированием по нажатию, оборачивает
  **ровно** номер (кошелёк, начинающийся с цифр, не откусывается пополам —
  держит это `(?![\w/])`).
* `ui.build_mark(uid)` и `ui.admin_hint(uid, …)` — код сборки и советы
  набрать служебную команду показываются **только владельцу**. Перечни
  скрытого не переписываются руками: считаются из зарегистрированных
  команд минус `commandlist.PUBLIC`.
* Постоянная клавиатура (`keyboards/reply.py`) — только основное, ряды
  `(2, 2, 1)`, показывается один раз на продавца, убирается `/keyboard`.
  Нажатие приходит **обычным текстом**, поэтому подписи учитывает
  `CommandsEscapeForms`.

**Ограничения Telegram**: сообщение 4096 символов (`ui.LIMIT = 3900`,
`ui.clip`), `callback_data` — 64 байта. Курсор этого маркетплейса —
70+ символов base64, в кнопку не влезает; падает при этом **весь экран**.
`handlers/pager.py` держит курсоры в памяти (`_KEEP = 30` на сущность), в
кнопку едет номер. Номера при вытеснении не пересчитываются: сдвиг
превратил бы кнопку в переписке в кнопку на чужую страницу. Не нашёлся —
«список устарел», а не первая страница под видом следующей.

## 10. Наблюдение за приёмом обновлений

aiogram проглатывает ошибку опроса молча: `_listen_updates` ловит любое
исключение, пишет строчку в лог и повторяет вечно. Процесс жив, порт
слушает — а бот глухой.

`WatchPolling` в `main.py` — обработчик логгера `aiogram.dispatcher`:

```python
_POLLING_GRACE = 90.0

def polling_silent(now=None) -> bool:
    # тревога только по СТОЙКОМУ молчанию:
    # попытки не удаются дольше _POLLING_GRACE И за это время
    # не пришло ни одного обновления
```

* **Одна неудачная попытка — не «бот не получает сообщения».** Живой
  случай: владельцу пришла тревога на одном `Request timeout`, а бот в ту
  же минуту рисовал ему экраны. Конфликт двух ботов и вебхук сами не
  проходят — полторы минуты им ничего не стоят, а икота уйдёт.
* **Пришедшее обновление отменяет тревогу** (`NoticeUpdates`) — оно
  доказывает, что приём работает.
* **Отбой обязателен**: `recovered()` говорит «✅ Входящие снова приходят»,
  но только если о беде говорили.

Две причины немоты приходят одинаково (409 Conflict) и лечатся
противоположно: второй экземпляр с тем же токеном либо вебхук на токене.
`polling_trouble()` не выбирает наугад — если текст Telegram не называет
причину, так и пишет: «причины две».

`/health` (на `$PORT`) отдаёт:

```json
{"status": "ok|deaf", "version": "…", "storage": "postgres|files",
 "polling": "ok|…", "webhook": "", "last_update_ago": 12}
```

`status: deaf` означает «процесс жив, но Telegram нас не слышит».

## 11. Диагностика

Метод проекта: **сначала диагностика, потом починка**. Каждая многочасовая
яма начиналась с догадки о том, что возвращает сервер, и закрывалась
read-only командой, печатающей факты.

| Команда | Что показывает |
|---|---|
| `/version` | версия, хранилище, токен, куки панели, состояние опроса |
| `/chat_debug <заказ>` | всю цепочку по чату: очередь → сообщения → «дочитано» → правило и пауза → примет ли маркетплейс ответ |
| `/order_debug <заказ>` | цена в списке против цены в карточке, сырой статус, почему не взят |
| `/stock_debug <объявление> [строка]` | что маркетплейс отвечает по остаткам; со строкой — отправляет её тем же вызовом и печатает сырой ответ до и после |
| `/copy_debug <объявление>` | что копия видит у товара: форма правки, карточка, `values`/`extra`/`labels`, форма создания, сколько вариантов отдаёт панель |
| `/panel_map`, `/panel_debug` | разделы панели |
| `/apr_debug`, `/apr_whoami`, `/apr_item`, `/apr_stock`, `/apr_balance` | AppRoute: сырой конверт, наш IP, цена и остаток номинала |
| `/ns_stock`, `/ns_balance` | каталог и баланс ns.gifts |
| `/fragment_debug`, `/fragment_cookies`, `/stars_probe` | сессия Fragment |
| `/stats_debug`, `/cat_debug`, `/pos_debug`, `/restore_debug`, `/withdraw_debug` | статистика, каталог, позиция, восстановление, вывод |

**Граница публичности проходит не по слову «debug», а по тому, чьё
устройство команда показывает.** Кабинет поставщика и сессия Fragment
принадлежат продавцу — эти команды остались ему. Скрыто то, что показывает
сам бот: выкат, хранилище, разбор ответов маркетплейса и панели.

Скрытая команда отвечает продавцу **ровно то же, что несуществующая**.

## 12. Тесты

```bash
pip install -r bot/requirements.txt
cd bot && python -m unittest discover -s tests -p "test_*.py"
```

3199 тестов в 107 файлах, ноль падений, в том числе в перемешанном
порядке. Если падает полтора десятка — почти наверняка не хватает
зависимостей: без `cffi` битая сборка `cryptography` роняет все тесты
шифрования, без `python-dotenv` не импортируется `config.py` и четыре
модуля тестов не загружаются вовсе.

Правила:

1. **Имя теста — предложение о поведении**, не о функции:
   `test_a_closed_chat_does_not_advise_answering_by_hand`. Докстринг
   класса объясняет, какая беда случалась раньше.
2. **Прогон в перемешанном порядке обязателен.** Подменяете что-то в общем
   модуле — откатывайте в `tearDown`/`tearDownModule`.
3. **Тесты пишутся до `if __name__ == "__main__"`** — дописанные после
   просто не выполняются.
4. **Проверяйте следствие, а не текст.** В платных функциях — какой товар
   списан и сколько раз, а не как выглядит сообщение.
5. **Тест, не падающий при откате правки, ничего не проверяет.** Убедитесь,
   что падает (мутационная проверка).

Отдельный класс — **тесты по настоящему HTTP**: `test_ad_copy_live.py`
поднимает подставную Nova, и по ней ходит тот же код (чтение полей, сборка
multipart, разбор ответа). `test_ad_copy_as_panel_answers.py` — панель,
отвечающая так же, как ответила живая: девять полей формы правки, двадцать
два поля формы создания, 825 разделов, четыре типа выдачи. Заглушками это
не проверить — именно там нашлись `NameError` в таймаутах, подраздел вместо
раздела и отладка вместо причины.

Тесты-сторожа: `test_dead_buttons.py` (удалённые методы не вернулись),
`test_hidden_commands.py` (список публичных команд закрытый),
`test_logs.py` (AST-разбор аргументов `log_event`: ни `token`, ни `cookie`,
ни `mnemonic`, ни `password`, ни `api_key`, ни `secret`),
`test_voice.py` (граница «ты» продавцу / «вы» покупателю),
`test_chat_chain.py` (дублей имён команд нет),
`test_pricing.py` и `test_trial_gate.py` (документы обещают то же, что
делает код).

## 13. Деплой

Два пути (подробно — `docs/DEPLOY.md`):

1. **Railway** — собирает и выкатывает при пуше в подключённую ветку
   (`railway.json` + `Dockerfile`, Chromium в образе нет).
2. **Свой сервер по SSH** — `.github/workflows/deploy-bot.yml` запускает
   `scripts/deploy.sh`. Нужны секреты `SSH_HOST`, `SSH_USER`, `SSH_KEY`,
   `DEPLOY_PATH`.

`scripts/deploy.sh` **сам сверяет версию через `/health`** и при
несовпадении объявляет выкат неудачным и откатывает код. Без `PORT`
сверять нечем, и скрипт говорит об этом прямо.

Подводные камни, найденные живыми прогонами:

* **`[ условие ] && команда` последней строкой функции обрывает скрипт под
  `set -e`**: при ложном условии функция возвращает 1, и вызов гибнет молча.
* **Повторный запуск установки не должен ничего спрашивать**: `uv venv` на
  существующем окружении спрашивает «заменить?». Решает скрипт: та же
  версия — `--allow-existing`, другая — `--clear`.
* **PostgreSQL без прав администратора** (`scripts/setup-postgres-user.sh`):
  сборки с Maven Central урезаны — ни `psql`, ни `createdb`, ни `pg_dump`.
  Базу заводит драйвер, копии снимает `scripts/db_tool.py` читаемым JSON
  того же вида, что и файлы хранилища.
* **`Type=notify` этой сборке противопоказан** — в двоичном файле нет
  `sd_notify`. `Type=simple` + `ExecStartPost`, ждущий сокет.
* **Перенос данных запускается с окружением бота целиком**, а не с одним
  `DATABASE_URL`: без `DATA_DIR` инструмент честно пишет «пусто в файлах»,
  а скрипт переключил бы бота на пустую базу. Итог переноса **сверяется**.
* **Два бота с одним токеном конфликтуют**; вебхук на токене глушит
  polling полностью при живой отправке.

## 14. Инварианты — что нельзя нарушать

Это не стиль, а причины прошлых поломок.

**Бот не должен врать.**

1. **HTTP 200 — не доказательство.** Сделали изменение — перечитайте и
   сравните.
2. **Каждое «ничего не произошло» объясняется** там, где причину увидит
   продавец (`conf["last_skip"]`, журнал автоответов, `poll["error"]`).
3. **Догадка не подаётся как факт.** Отказ ещё не случился — так и пишите.
4. **Не советуйте невозможного.** `explain_error` возвращает вторым
   значением «можно ли исправить вручную» — совет зависит от него.
5. **Английский код ошибки на экране продавца — отписка.** Переводите;
   код остаётся в скобках, ведёт русская фраза.

**Никогда не управляйте логикой по тексту собственного отчёта.** Был
случай `guest = any("не видно входа" in line for line in report)`. Факты
собирайте в dict, признаки возвращайте значениями.

**Два голоса.** Продавцу — на «ты», покупателю продавца — на «вы». Голос
покупателя живёт в `bot/autoreply.py`, `STARS_TEXTS`, всём, что уходит
через `_send_chat`, полях `activation` в `giftcards.py` и шаблонах в
`_DEFAULT_SETTINGS`. Границу держит `test_voice.py`.

**Списки слов для распознавания — это данные, а не текст.** Массовая
замена под «ты» однажды превратила `_COMPLAINT_KEYWORDS` «верните» в
«верни» — то есть молча отключила распознавание споров. И `\b` перед
кириллицей не работает после `\n` в исходнике: границу надо считать по
самой кириллице, `(?<![А-Яа-яЁё])`.

**Секреты.** Куки Fragment и seed-фраза TON никогда не попадают в логи, в
отчёты диагностики и в репозиторий — в диагностике печатается только длина
(«stel_token: 39 символов»). Прокси показывается только хостом и портом.

**Одно знание — одно место.** Курсор разбирает `next_cursor()`, позиции
читает `ad_items_free`, остаток срока говорит `_left_line`, экран поддержки
собирает `support.py`, заслон плагина стоит один на роутер. Разложенное по
местам однажды не сойдётся само с собой, и разойтись это может молча.

**Версия поднимается при каждом значимом изменении.** Без `BOT_VERSION`
невозможно отличить «не работает» от «не задеплоено».
