# Чек-лист до первой живой покупки

Проходить **по порядку**. Каждый пункт закрывает случай, который уже
случался, и почти все они денежные.

---

## A. Ключ поставщика

- [ ] Ключ создан, право **`orders:write`** выдано
      *(без него ключ покупает, но кода не отдаёт: деньги списаны, выдать нечего)*
- [ ] На счёте у поставщика есть деньги
- [ ] Проверено, каким адресом поставщик нас видит
- [ ] Если адрес сервера меняется при выкате — поставлен прокси с постоянным
      адресом, и он **вписан в белый список**
- [ ] Прокси проверен **проверкой**, а не предположением: адрес спрошен
      трижды и сверен с прямым
- [ ] Через прокси идут и рабочие вызовы, и диагностика

## B. Адаптер площадки

- [ ] `paid_orders()` возвращает **только оплаченные**
- [ ] Список **дочитывается до конца** — число совпадает с кабинетом
- [ ] `is_paid()` проверен на **живом** заказе, а не по документации
- [ ] `chat_id` найден и он **не равен** номеру заказа (или равен — проверено)
- [ ] `description` доезжает: регион читать неоткуда без него
- [ ] `send_message()` возвращает причину **по-русски**
- [ ] Известно, что площадка отвечает при превышении темпа
- [ ] Известно, можно ли писать в закрытый заказ

## C. Каталог и подбор

- [ ] `catalog_of()` отдаёт номиналы с `in_stock` и `price`
- [ ] Каталог **кешируется** (`GET /services` — 2 запроса в минуту)
- [ ] Номинал читается из названия товара правильно: проверено на трёх
      настоящих названиях, включая «10 USD (1000 Robux)»
- [ ] Регион читается из описания: проверено на настоящем описании
- [ ] Товар без региона в описании даёт **отказ с причиной**, а не покупку
      наугад

## D. Движок

- [ ] `python3 -m unittest discover tests` — зелено (20 тестов)
- [ ] Префикс ссылки (`reference_prefix`) **отличается** от того, что
      используется на других площадках того же кабинета
- [ ] `resume_unfinished()` зовётся **каждый проход**, а не только при старте

## E. Живая проба — на самом дешёвом номинале

- [ ] Тестовый заказ оплачен, код пришёл покупателю
- [ ] В журнале есть запись: номинал, цена, ссылка, состояние «выдан»
- [ ] Второй проход по тому же заказу **не покупает** второй раз
- [ ] Заказ в статусе «создан» (не оплачен) **не выдаётся**
- [ ] Заказ с номиналом, которого нет у поставщика, даёт отказ с перечнем
      того, что есть

## F. Обрыв — главная проверка дня

- [ ] Процесс убит между покупкой и отправкой
- [ ] После перезапуска `resume_unfinished()` **дослал** код
- [ ] Второй покупки **не было** (проверить по кабинету поставщика)
- [ ] Отправка временно сломана → код **записан** в журнал и показан продавцу
- [ ] Отправка починена → код ушёл, заказ отмечен выданным

## G. Отказы говорят по-русски

- [ ] Нет ключа → понятная причина, а не `UNAUTHORIZED`
- [ ] Нет денег у поставщика → понятная причина
- [ ] Номинал кончился → «денег не потрачено» сказано прямо
- [ ] В каждом отказе есть `traceId`
- [ ] Продавец получает уведомление при **любой** беде

## H. Интерфейс продавца

- [ ] Включить / выключить вид товара
- [ ] Ввод ключа поставщика — **шифруется** в хранилище
- [ ] Ключ, куки и коды **не попадают в журналы**
- [ ] Журнал выдач виден: что, когда, почём
- [ ] Ручная выдача по номеру заказа идёт **тем же путём**
- [ ] Регион и слово-опознаватель настраиваются

## Что проверить ещё раз перед тем, как включить всем

- [ ] Плагин **выключен по умолчанию** у нового продавца
- [ ] Продавец видит, что выдача тратит **его** деньги у поставщика
- [ ] При кончающемся балансе у поставщика приходит предупреждение
      **заранее**, а не в момент отказа
- [ ] Есть способ выключить всё одной кнопкой
