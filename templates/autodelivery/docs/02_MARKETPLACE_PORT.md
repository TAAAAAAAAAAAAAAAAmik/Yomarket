# Порт площадки: что писать под PlayerOK

Единственный файл, который надо написать самому: `code/marketplace.py`,
класс с пятью методами.

**Предупреждение.** API PlayerOK в этом шаблоне не проверялось. Ни одного
имени поля, ни одного статуса, ни одного адреса здесь нет — их надо выяснить.
Выдуманные значения в этом месте стоят денег: рядом идёт покупка.

---

## Пять методов

### 1. `paid_orders() -> list[Order]`

Заказы, которые **оплачены** и ещё не обработаны нами.

Что важно:
* возвращать только оплаченные. «Создан» деньгами не является — на таком
  заказе площадки обычно сами пишут «не выдавайте товар». Ошибка здесь =
  выдача бесплатно;
* **дочитывать страницы**. Первая страница — это не «все». На исходной
  площадке четырнадцать мест читали только первую и молча теряли половину;
* не фильтровать по виду товара — это решает движок.

### 2. `get_order(order_id) -> Order | None`

Один заказ по номеру. Нужен возобновлению: оно идёт из журнала, и карточки
заказа под рукой у него нет.

### 3. `send_message(chat_id, text) -> (bool, str)`

Написать покупателю. Второе значение — причина **по-русски**, и она нужна
всегда, даже при успехе: журнал показывает её продавцу.

Переводить обязательно: голый код ошибки на экране продавца — это
«разбирайся сам».

### 4. `is_paid(status) -> bool`

Означает ли статус, что деньги у продавца. Отдельным методом, потому что у
каждой площадки свой словарь и он меняется.

### 5. `order_url(order_id) -> str`

Ссылка на заказ в кабинете, для уведомлений. Пустая строка — законный ответ.

## Девять вопросов до первой строчки кода

Те же, что в докстринге заглушки. Ответы записывай туда же.

| № | Вопрос | Чем грозит неверный ответ |
|---|---|---|
| 1 | Как авторизуемся: токен, куки, что-то ещё? | не заработает вовсе |
| 2 | Опрос или вебхук? Какой период разрешён? | бан за темп либо пропущенные заказы |
| 3 | **Какие статусы означают «оплачено»?** | **выдача бесплатно** |
| 4 | Списки страницами? Курсор или номер? | половина заказов не существует |
| 5 | Номер чата = номер заказа? | код уходит в никуда |
| 6 | Можно ли писать в закрытый заказ? | совет «ответьте вручную» туда, куда не пустят |
| 7 | Где описание товара? | регион не прочитается, выдача встанет |
| 8 | Что отвечает при превышении темпа? | долбёжка в стену вместо отступа |
| 9 | Идемпотентна ли отправка сообщения? | покупатель получит код дважды |

Третий вопрос — единственный, ошибка в котором отдаёт товар даром. Проверяй
его на своём тестовом заказе, а не по документации.

## Как узнавать о новых заказах

### Если опрос

```python
while True:
    for order in await market.paid_orders():
        if already_seen(order.id):
            continue
        await engine.on_paid_order(order)
    await engine.resume_unfinished()      # каждый проход, обязательно
    await asyncio.sleep(PERIOD)
```

Период выясняется у площадки, а не угадывается. Если она отвечает «сбавьте
темп» — отступать **вдвое**, до потолка, и понемногу возвращаться. Угаданное
число даёт либо медленно, либо бан.

### Если вебхук

Тогда есть два подвоха:
* **повторная доставка события будет.** Движок к ней готов (`delivered`,
  запись в журнале, постоянная ссылка), но проверь, что твой обработчик не
  создаёт вторую запись;
* **возобновление всё равно нужно.** Вебхук не придёт повторно, если процесс
  умер посреди выдачи. `resume_unfinished()` надо звать по таймеру
  независимо от вебхуков.

## Чего в адаптере быть НЕ должно

| Не место | Где это живёт |
|---|---|
| Решения, покупать ли | движок |
| Подбора номинала | `catalog.py` |
| Записи в журнал | движок |
| Вызовов поставщика | `supplier.py` |
| Текста сообщения с кодом | движок |

Адаптер только переводит форматы: ответ площадки → `Order`, текст → отправка.
Как только в нём появляется «если статус такой, то купить» — конвейер
раздваивается, и дальше он разъедется.

---

## Проверка, что адаптер готов

```python
market = PlayerokMarketplace(token=...)
orders = await market.paid_orders()
assert orders, "не видим оплаченных заказов"

o = orders[0]
assert o.chat_id, "не нашли номер чата"
assert o.description, "не нашли описание — регион читать неоткуда"
assert market.is_paid(o.status), "статус оплаты определяется неверно"

ok, why = await market.send_message(o.chat_id, "проверка связи")
assert ok, why
```

Пять строк, и они закрывают четыре из девяти вопросов. Остальное — тестами
движка, они адаптера не требуют.
